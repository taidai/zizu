# 光储充 EMS 独立交付试验协议

本协议是 ZiZu “交付就绪”的最终人工证据模板。它不是开发验收，也不能由单元测试、开发人员
演示或合并记录替代。

## 通过条件

一位未参与 ZiZu 开发的实施工程师，在四小时内、从干净备用环境开始，只使用公开发布制品、
公开文档、已发布的光储充 EMS 解决方案包、产品界面和公开 API，完成一次单站交付。机器验收
报告的全部必需项必须通过。

以下任一行为使本次试验失败：修改平台源码、直接访问数据库、运行未公开的一次性脚本、使用
客户拓扑或凭据、开发人员口头指导完成关键步骤，或超过四小时。

## 试验前门禁

计时前由试验观察员逐项确认；任何一项缺失都不得启动计时。

| 门禁 | 必需证据 |
| --- | --- |
| 固定发布制品 | `release.json`、目标架构的 digest-only `release.env` 与预检通过记录 |
| TLS 入口 | 浏览器通过 HTTPS 访问，HTTP 不承载登录或 Bearer 凭据 |
| 发布锁定 | 当前目标的不可变 release lock 与平台版本、Schema、包摘要、站点配置版本一致 |
| 数据库安全 | owner/app 角色迁移已执行；web 使用非 owner 应用角色；启动健康门禁通过 |
| 试验环境 | 新建、隔离的单站实例；公开协议模拟器或独立测试设备；不连接客户现场 |
| 参与者 | 实施工程师姓名/代号、与项目关系、未参与开发声明；观察员姓名/代号 |
| 输入制品 | 发布 ZIP 的 SHA-256、文档版本/提交、平台 release lock ID |

观察员保存这些值到试验记录；凭据仅由部署秘密系统保存，绝不写入记录或仓库。

## 允许与禁止的材料

实施工程师可使用 README、发布说明、参考包 README、产品 UI、OpenAPI 与公开 API。可以使用
包中声明的参数契约、Secret 引用名称和协议模拟器。

不得使用源码、数据库终端、内部 Python 对象、宿主机源码挂载、未发布脚本、聊天中给出的现场
参数或开发人员代操作。遇到阻断时记录时间、公开错误码和所查阅的公开文档；观察员不得给出
操作路径提示。

## 计时步骤与证据

| 阶段 | 实施工程师动作 | 必须留下的公开证据 | 交付能力 |
| --- | --- | --- | --- |
| 1 | 登录并确认当前发布锁和版本 | HTTPS 页面/API 响应、release lock 摘要 | 部署运维 |
| 2 | 接入或确认五类测试节点，设置稳定目录键与规范点位 | 节点/点位界面或 API 导出；不得含真实地址/凭据 | 设备接入 |
| 3 | 导入已发布 EMS ZIP，填写参数契约与 Secret 引用 | 导入结果、计划摘要、无 blocker 的安装计划 | 配置式交付 |
| 4 | 审查并执行幂等安装，确认实体实例与唯一绑定 | 安装结果、实体实例列表、确定绑定证据 | 监控基础 |
| 5 | 经协议模拟器或测试设备发送 GOOD 样本，查看实时值和历史 | 实体实时读数、历史就绪/趋势证据 | 监控、历史 |
| 6 | 触发、确认并由现场条件恢复分级告警 | 告警事件状态序列与确认主体 | 分级告警、操作审计 |
| 7 | 以操作员身份提交一个受限手动控制，完成回读确认 | 控制命令 ID、联锁/冷却结果、`readback_confirmed` | 手动控制 |
| 8 | 以实施工程师身份仿真并启用基础策略，在合格输入下执行声明动作，再停用 | 仿真、启停审计、命令 ID、回读；参考包仅允许 10 kW 隔离动作 | 基础策略、自动控制 |
| 9 | 运行解决方案包验收清单并导出报告 | 不可变 delivery report；全部 required 项 `passed` | 八项总验收 |

每个阶段记录开始/结束时间、使用的公开页面/API、得到的资源 ID、结果和阻断原因。实际站点
参数、账号、令牌、IP、设备序列号及 Secret 不得写入试验记录。

## 配置覆盖率

观察员对该次交付列出点位、实体实例、告警定义和策略动作总数。通过解决方案包、安装参数、
受保护 UI 或公开 API 完成的项目为“配置完成”；修改源码、SQL 或一次性脚本完成的项目为零分。

`配置覆盖率 = 配置完成项目数 / 全部项目数 × 100%`。

通过门槛为至少 90%，并在记录中分别给出四类项目的分子、分母和任何排除理由。

## 试验记录模板

```text
试验编号：
日期与时区：
实施工程师（未参与开发声明）：
观察员：
平台 release lock ID / 版本 / 架构：
EMS ZIP SHA-256：
开始时间：
结束时间：

阶段 1..9：开始、结束、公开资源 ID/报告 ID、结果、阻断原因（如有）

配置覆盖率：点位 __/__；实体实例 __/__；告警 __/__；策略 __/__；总计 __%
验收报告 ID / 总体状态：
结论：通过 / 失败
失败原因与后续 Issue：
观察员签字/电子确认：
```

试验通过后，记录可作为不含现场私有数据的发布附件；失败记录同样保留，并把每个失败原因转为
可追踪的后续事项。试验本身不会授予上线权限：生产切换仍需单独的维护窗、回滚预检和业主授权。
