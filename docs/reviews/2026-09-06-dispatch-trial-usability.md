# 调度试算易用性修复（2026-09-06）

## 本轮范围

用户确认先让现有功能完整好用，性能专项后置。本轮只修现有调度试算，不新增模块、运行模式、依赖或 Schema，不修改质量、时效、联锁和真实控制条件。

## 根因与修复

1. **查看已发布策略也会制造草稿。** 前端每次试算都先保存；后端只允许草稿或活动修订，不接受已发布但停用的版本。现在页面无编辑时直接试算所见修订；有编辑时先保存再试算。API 允许当前策略的草稿、活动修订及最新已发布修订，仍拒绝其他策略或不在白名单内的修订。
2. **阻断被显示成“无需控制”。** `BLOCKED` 没有计算结果，原页面却同时显示“未命中”“无需控制”和成功提示。现在明确显示“未执行计算”“未生成控制意图”，用中文解释阻断原因并保留错误码；展示本次输入快照的值、单位、质量和时间。采集质量正常不等于数据仍新鲜。
3. **同一草稿 ID 可能已被他人修改。** 页面随试算提交所见 `content_digest`，运行时在读取输入及执行 JDM 前核对实际加载版本，不一致返回既有 `STRATEGY_DRAFT_CONFLICT`。API 的 `expected_digest` 为可选字段，未提供时仍按当前修订试算。
4. **修订内容与绑定可能来自两次编辑。** 仓储读取修订及绑定使用同一只读 REPEATABLE READ 事务，防止旧摘要和新绑定混读。事务结束后释放，不修改数据库全局参数。

试算仍不生成可执行控制意图、不写设备、不改变发布/启用/故障锁状态。非法表单会清除旧结果并阻止试算，不用上次合法 JDM 冒充当前输入。
