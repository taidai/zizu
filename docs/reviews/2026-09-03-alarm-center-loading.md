# 告警中心加载慢：根因、修复与证据

日期：2026-09-03。基础版本 v0.7.7，Schema060 不变。

## 根因

- 当前告警接口为了显示 1～2 条记录，每次调用 `runtime.list()` 读取全部 6,121 条事件，
  包括三份观测 JSON，再在 Python 中筛选、排序、分页。完整读取实测 4.19 秒，名称查询仅 0.041 秒。
- 1 号机本机公开接口连续实测 4.536 / 6.845 秒；匿名存活接口 0.028 秒。
  数据库按当前状态筛选的查询计划执行时间仅 0.953ms，主要瓶颈是无边界数据搬运与解码。
- 同步数据库读取直接运行在异步路由中，阻塞同进程事件循环。
- 页面首屏有重复加载 effect；5 秒轮询没有在途请求保护，刷新时还会隐藏已有列表。
  切换筛选后，迟到的旧响应可以覆盖新结果。

## 修复边界

1. 公共 API 形状不变，新增内部分页查询：数据库完成筛选、排序、分页和标量统计，只返回当前页事件。
   一条 SQL 保证计数与当前页来自同一快照；保留活动优先、全局统计、normal 排除和确定性 ID 排序。
2. 数据库查询和名称补充在工作线程执行，不阻塞数据帧所在的事件循环。
3. 前端统一加载入口：筛选时一并回到第一页，取消旧请求，丢弃过期响应；在途刷新不叠加请求。
   后台刷新保留上次列表，失败明确提示并可重试，不伪装成“无告警”。
4. 不新增依赖、缓存服务或数据库迁移，不改变告警判定、确认、恢复、HTTP 通知和设备控制。

## 验证

- PostgreSQL 公共查询专项使用当前连接的临时表，不写现场告警或运行配置。
  6,200 条历史 + 4 条状态样本：修复前断言失败（取回 6,204 行 > 50），修复后通过。
  覆盖活动/历史/严重度/实体过滤、越界空页、全局统计及 normal 排除。
- 第二项在数据库边界加入确定的延迟，真实 SQL 不替换：修复前异步心跳为 0，修复后可以继续运行。
  两项专项最终 2/2 通过。
- 在 1 号机单独 Python 进程内加载候选代码，只读查询同一现场库：当前告警 0.163 / 0.048 秒，
  历史首页 50 条 0.380 秒。未替换服务代码；此数据不是部署后的浏览器端到端耗时。
- 无头浏览器用真实前端与合成 HTTP 响应复现“刷新隐藏列表”“旧响应覆盖新筛选”，两项先红后绿，
  最终 2/2，通过耗时 3.5 秒；同时验证慢刷新期间不会继续叠加请求。无现场写入或消息发送。
- 后端规范 unittest 命令：510 项，191 项条件跳过，0 失败（21.452 秒）。
  `pytest tests -q` 也通过：382 passed，191 skipped，99 subtests passed。
  根目录旧 `test_f0_*` 脚本不属于上述 tests 目录；无参数 pytest 会因旧脚本缺少设置/字段而收集失败，
  本轮未顺带修改这些历史脚本。
- 发布脚本 56/56；前端全部 mjs 测试 88/88；TypeScript + Vite production build 通过。
  保留现有大 chunk、依赖弃用提示，不宣称无警告。
- Browser 在原站只读检查节点 → L0 → L1 数据来源与计算 → L2 → 告警入口，未发布配置或确认告警。
  本地前端通过代理提交现场密码被安全检查拒绝，未绕过；新页面使用合成数据验证。
