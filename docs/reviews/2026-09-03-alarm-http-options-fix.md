# 告警规则 HTTP 通知选项修复

## 根因与范围

现场 v0.7.8 管理接口读取成功；两项通知配置均有当前版本的成功测试，但都处于停用状态。
规则页直接过滤掉不可用项，因此只剩“不发送 HTTP 通知”，没有解释原因。
此外，实施工程师错误地调用仅管理员可用的管理接口，403 又被吞成空数组。

本次保留“测试成功且启用才可选择”的安全约束，不自动启用、测试或发送，不修改投递语义和数据库。

## 修复

- 新增 `GET /api/v1/alarm-http-notification-options`，需要 `configuration.read`。
  返回每项的 `id`、`name`、`status`：`available`、`disabled`、`needs_test`。
  不返回 URL、请求头、请求体、密钥、摘要或测试响应。原管理接口仍仅 admin 可用。
- 规则页单独加载通知选项，明确显示停用、需测试并启用、空配置和加载失败。
- 提示管理员在“系统工具 → HTTP 通知”维护；实施工程师需联系管理员。
- 增加“刷新通知选项”，不重载规则、不清空草稿或原绑定；请求失败保留选择，卸载时取消请求。
- 仍只允许选择可用通知；已绑定的通知不可用时保留绑定并提示，不偷偷改成“不发送”。
