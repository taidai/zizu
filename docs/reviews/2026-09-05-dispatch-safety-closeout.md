# 调度安全收尾（v0.8.8）

范围：收回 v0.8.7 调度策略的输入语义、无损编辑与旧意图安全缺口，不重做主干、不增加模式、引擎或 Schema。2026-09-05 用户进一步要求直接部署 1 号机测试；现场结果另记录，不将本机模拟视为 PCS 验收。

## 已实现

- 内置 SOC 必须为 `bms.soc` / `storage.soc`、数值 `%` 且值在 0～100；功率输出必须为可控数值 `kW`。草稿、发布、启用、试算、求值共用契约。
- 页面与后端均要求实体 active、真实节点 enabled、存在 current L1 输出；未确认或已停用来源不能进入策略。
- 领取旧待发/重试意图时检查 READY、所有权、活动修订、原始来源证据和当前 L2；缺失、过期、错误质量、错误 SOC 不可下发。取消同次求值剩余待发动作，避免顺序等待悬挂。
- 真正调用统一控制期间持有短提交栅栏：配置、策略、来源元数据及 L2 行锁。先完成的停用/配置/数据变化会被重新检查，后到的变化等待本次提交结束；不为后续回读持锁。冷却用同目标事务锁串行，避免跨连接实体锁升级自等待。
- 已下发命令即使停用、配置变化或证据过期也只继续回读。命令已保存但意图关联前崩溃时，按原策略身份和尝试幂等键恢复，不重复提交。
- 保留完整 JDM、触发方式、时区、全部绑定和新鲜度契约；24:00 保真，发布与启用分开显示。
