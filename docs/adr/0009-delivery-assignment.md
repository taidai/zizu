# ADR-0009：以交付分配向实施工程师授权固定解决方案包

## Status

Proposed — 2026-08-15

## Context

`solution.package.read` 只允许平台管理员，以避免把全量解决方案包目录作为普通工程师的浏览面；但
实施工程师已有计划、安装和验收权限。若没有可见的已选包与参数契约，工程师无法仅使用产品界面
完成交付。直接放宽包目录读取会把未分配的场景资产暴露给所有工程师，也不能说明管理员选定了哪一
个不可变交付基线。

产品目的地明确首版不建设工单、项目管理或审批系统，因此不能把此授权对象称为“工单”。

## Decision

新增 **交付分配** 作为单站实例中的最小授权记录：

- 平台管理员选择一个已验证的包记录和一名实施工程师，创建一条不可变包摘要绑定的分配；
- 实施工程师只能读取分配给自己的包的公开表示、参数契约和状态，并只能据此创建计划、安装和运行
  验收；
- 管理员可撤销尚未完成的分配。已产生安装或报告的分配保留为审计证据，不得被改写为另一包或另一
  实施工程师；
- 分配不保存 Secret 值、现场参数、排期、客户信息、成本或审批状态。

本 ADR 在交付分配的持久化、公开接口和界面均完成并通过工程师主缝前保持 Proposed；现有
`solution.install.*` 端点的宽泛 engineer 能力不能被视为本决策已经落地。

交付分配模块的接口只提供创建、列出/读取自身分配、撤销与在同一分配下执行计划/安装/验收四类
行为；包校验、计划摘要、幂等、实体绑定和报告仍由 `SolutionDelivery` 深模块负责，分配不复制
这些规则。

## Consequences

- 实施工程师可通过最小公开产品面完成完整交付，而管理员仍控制包生命周期和可见范围。
- 前端交付向导以“我的交付分配”为入口，不要求工程师知道数据库包 UUID 或使用源码/SQL。
- 首版不引入通用工单系统；若未来需要排程、审批或多站项目管理，必须另立 ADR，而不能扩大本对象。
