# ADR-0014：单站实时黑板与提交后数据帧

ZiZu 的秒级数据主干采用每站一块进程内实时黑板和一个默认 1 秒的统一拍照节拍：只在有新样本或
质量变化时冻结完整数据帧，先批量持久化帧与变化 L0，再以固定配置修订运行一次完整 L1，最后原子
提交 L0 latest、L2、来源证据和 outbox；点位诊断页只能消费提交后的 L0，告警、JDM、控制、EMS
工作台和业务画面只能消费提交后的 L2。
数据帧使用共享类型化 L0/L2 时序表与一张帧元数据表，不保存巨型 JSON，也不引入 Redis、Kafka、
逐点节拍或分层超级表。同一单站只允许一个活动采集写者持有黑板，首版不支持 active-active backend。
现有 L2 outbox 硬切为每个终态帧一条的统一数据帧 outbox，同时承载 L0/L2 的提交后实时送达。
数据帧保存持续递增的拍号，每条新 L0 保存实际到达拍号，使只有变化 L0 落库时仍可在重启后精确重建
STALE；不为此增加全量帧明细表。

该选择明确接受迟到/重复样本直接丢弃、同一节拍只保留每点最后样本，以及进程在拍照前崩溃时最多
损失一拍尚未提交候选的代价，以换取逻辑一致的计算切面、有界数据库写入和可恢复处理。启动或必需
输入集合变化后，只有活动 L1 依赖的全部必需 L0 收到本轮新样本才进入 READY；连续三拍未更新的
格子保留旧值但质量变为 STALE。帧处理失败不得回滚已提交 L0，必须在固定预算内失败告警、使相关
L2 陈旧并继续后续帧。本决策补充 ADR-0011 与 ADR-0013；窗口统计仍遵循 ADR-0012，不并入帧内 L1。
它同时取代旧数据主干规格中“迟到观测仍写 L0 历史”和“STALE 必须清空值”的语义：迟到数据直接
丢弃，STALE 保留最后已知值供诊断，但所有机器消费者必须按质量 fail closed；它也取代即时 L2 的
逐实体周期历史与心跳，统一改由站级变化帧提交。配置发布前必须清空旧帧与未发布 outbox，切换后旧
修订结果不得驱动业务；latest 统一按帧序号推进，失败范围扩展到强类型 DAG 的全部下游闭包。旧 EN9
的每输入 5 秒下限由“三个站级节拍 + 发布时采集周期校验”取代。已排队自动控制在设备写入前必须
重验来源配置修订，旧修订命令 fail closed。
