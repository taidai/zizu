# ADR-0008：受控的小功率高风险策略自动化

## Status

Accepted — 2026-08-14

## Context

ADR-0007 要求 `highRisk: true` 的人工控制逐次二次确认。光储充 EMS 同时需要一个可复用、
可审计的基础策略能力；维护者只授权在隔离参考交付中以 10 kW 验证，不授权把该值当作现场默认。

## Decision

1. 高风险控制默认继续要求人工二次确认。唯一例外仅限已安装的 `ems_policy` 资产，绝不适用于
   规则、兼容 API 或手动 HTTP 请求。
2. 例外必须由包内动作显式声明 `highRiskAuthorization.maximumAbsoluteValue`。动作和上限均须为
   有限数值，动作绝对值不得超过上限；平台仍执行目标的既有限值、联锁、冷却和回读。
3. 只有 `engineer` 能在当前站点配置版本对策略执行 `enable`/`disable`。升级形成新站点配置版本后
   必须重新启用。统一控制运行时在分派前由服务端重新核对当前已安装策略、revision、动作、目标、
   值、上限和激活状态；仅本次策略运行时可签发进程内、不可持久化的授权证明。命令携带的证据字典
   只用于审计，不能单独构成绕过二次确认的权限。
4. 评估持有激活记录的共享锁直到统一命令完成分派记录；`disable` 的删除锁在返回前等待这一临界区。
   因此停用成功返回后，不会有此前尚未分派的评估再开始下发；已分派命令只可由回读、失败或超时收敛。
5. 参考包的 10 kW 只用于协议模拟与交付演练。生产场站必须由实施工程师根据设备铭牌、并网约束、
   风险评估和联锁重新发布包版本或站点配置，不能复用此值作为安全许可。

## Test seam

通过公开 HTTP 的 `simulate → enable → evaluate → control-command/reconcile` 和协议模拟器回读验证。
测试还必须证明：未声明例外的高风险策略仍被拒绝、超出包内上限的资产无法导入、非 engineer 无法
启停策略，停用与评估并发时停用返回后不产生新的分派命令。
