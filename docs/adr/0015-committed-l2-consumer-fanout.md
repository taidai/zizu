# ADR-0015：提交后 L2 消费者共用有序帧分发

告警、JDM、控制和 EMS 工作台统一从 `t_data_frame_outbox` 的终态帧消费 L2，不再轮询 latest、订阅原始
MQTT 或建立模块私有 outbox。分发保持站级帧序和 at-least-once：只有全部已注册消费者成功后才把帧标为
已发布；状态型消费者在自己的业务事务内写入 `(consumer_key, frame_id)` 收据，使进程在业务提交后、
全局发布前崩溃时重放不会重复改变状态。浏览器实时流继续按帧序幂等去重，不写消费收据。

选择这一方案，是为了让所有上层模块共享事务 B 之后的唯一事实和配置排空栅栏。把上层逻辑塞进事务 B
会扩大采集写事务并违反提交后可见；各模块自行轮询或各建 outbox 会重新制造时序分叉；只依赖状态机
“看起来可重入”无法覆盖触发与恢复条件重叠、部分处理后崩溃等边界。代价是任一关键消费者失败会让
outbox 队头保持未发布并阻止配置切换，但采集和数据帧提交仍继续，故障可观测且恢复后按原序重放。
