# ZiZu 产品目的地

## 产品定位

ZiZu 是面向工业控制系统交付的开源物联网低代码平台。首要使用者是系统集成商和实施工程师；他们通过配置完成项目交付，业主操作员使用交付后的系统进行日常运行。

## 首个参考交付

光储充 EMS 是首个参考交付。达到交付就绪至少包括：

- 设备接入；
- 实时监控；
- 历史数据；
- 分级告警；
- 手动与自动控制；
- 基础能源策略；
- 操作审计；
- 部署与运维。

计费、工单、移动端和多租户不属于首版参考交付。

## 配置式交付验收

在协议驱动与设备模板已经存在的前提下，新站点应满足：

- 无需修改 ZiZu 平台源码；
- 四小时内完成站点配置；
- 至少 90% 的点位、实体、告警和策略通过模板导入与界面配置完成；
- 交付结果通过可重复执行的自动验收和现场验收。

## 解决方案包

配置式交付以版本化解决方案包为单位，而不是逐个复制零散模板。光储充 EMS 解决方案包组合：

- 节点结构与参数契约；
- 设备模板；
- 实体定义与绑定规则；
- 告警等级、条件与故障码；
- 控制策略与输入输出映射；
- 运行页面配置；
- 机器可执行验收清单。

站点配置只实例化现场参数和实际设备映射，不复制平台代码，也不携带凭据。

解决方案包采用可进入 Git 版本控制的声明式目录，而不是数据库备份。根目录包含解决方案清单，资产使用 YAML/JSON 表达，并必须支持：

- Schema 校验；
- 包版本与平台兼容范围；
- 安装前差异预览；
- 幂等安装；
- 可审计升级。

解决方案包通过参数契约描述现场差异。参数必须声明名称、类型、单位、必填性、默认值、允许范围和是否敏感。实施工程师通过安装向导填写；敏感参数只保存运行时 Secret 引用，不进入解决方案包、站点导出或交付报告。

升级使用三方差异：旧解决方案包、当前站点配置、新解决方案包。升级前展示新增、删除、变更和冲突；站点覆盖与人工绑定默认保留，冲突必须由实施工程师明确处理，禁止静默覆盖。

## EMS 运行工作台

首版不建设通用拖拽大屏设计器。光储充 EMS 提供固定的运行工作台，解决方案包只配置：

- 导航入口；
- 设备与能源子系统分组；
- 关键指标及其实体引用；
- 趋势图实体集合与默认时间范围；
- 告警和控制入口的可见性。

布局组件库和允许的页面结构由平台版本控制，避免解决方案包携带任意前端代码。

## 站点与控制边界

首版采用单实例单站。数据结构可以保留未来引入 `site_id` 的演进空间，但多租户和跨站管理不进入首版。

所有操作员手动控制和自动策略控制统一产生控制命令，并经过同一入口执行权限、限值、联锁、幂等、冷却时间、审计和写后回读。页面、规则或其他模块不得绕过该入口直接写设备。

控制命令状态至少包括：已受理、校验通过、已下发、回读确认；终止状态包括拒绝、超时、失败和结果不一致。写接口返回成功不代表控制完成，只有回读确认满足命令声明的期望值、容差和超时才算成功。

## 实体与绑定

实体模型分为实体定义和实体实例。实体定义表达跨设备复用的标准语义；实体实例表达站点内实际对象的运行语义。规则、EMS 运行工作台、告警和控制统一引用实体实例 ID。

解决方案包声明实例槽位，站点参数决定实例数量与标识。安装或升级阶段必须为必需实体实例形成确定性绑定：

- 唯一候选可进入待确认或按包内明确规则自动确认；
- 零候选视为缺失；
- 多候选视为歧义；
- 缺失和歧义均阻止交付就绪；
- 运行时禁止按优先级或创建顺序静默选择数据源。

若需要主备数据源，应由显式故障切换策略表达，不复用歧义绑定机制。

## 告警语义

告警由现场观测驱动，统一状态至少包括：正常、待触发、活动未确认、活动已确认和已恢复。告警定义支持持续时间、迟滞、恢复条件和通知节流。

确认只表示业主操作员已经知悉活动告警，不改变现场状态；恢复只由现场恢复条件产生，人工不能直接把仍在发生的故障标记为恢复。MQTT、标签和实体告警作为来源适配器进入同一告警状态接口，不再各自维护不同的状态语义。

## 交付报告

解决方案包的验收清单至少自动检查：

- 设备与协议网关在线；
- 必需实体绑定完整且无歧义；
- 实时数据新鲜；
- 告警能够触发、确认和按现场条件恢复；
- 控制命令成功写入并完成回读；
- 基础策略可以仿真且输入完整；
- 操作产生完整审计记录。

验收运行生成带解决方案包版本、站点配置版本、执行时间和逐项证据的交付报告。

## 身份与权限

首版定义三种运行角色：

- `admin`：平台安装、解决方案包生命周期、系统配置和用户管理；
- `engineer`：设备、实体绑定、告警、策略配置和交付验收；
- `operator`：运行监控、告警确认和被授权的控制命令。

高风险控制在角色权限之上继续使用命令级策略，并可要求二次确认。所有权限必须由服务端校验，页面可见性不构成安全边界。

生产模式默认要求所有业务 REST API 和 WebSocket 完成认证，仅最小存活探针允许匿名访问。开发模式可以显式开启匿名访问，但运行状态和界面必须醒目标记为不安全；不得通过缺省配置隐式进入匿名模式。

## 发布与回滚

平台发布固定版本的多架构容器镜像并提供内容摘要；解决方案包独立使用语义版本。每次部署形成发布锁定，至少记录：

- 平台版本；
- 容器镜像 digest；
- 数据库 Schema/迁移版本；
- 解决方案包版本；
- 站点配置版本。

部署、升级和回滚只能使用可验证的不可变制品，不使用 `latest` 或宿主机源码覆盖作为正式交付方式。

## 四小时交付试验

配置式交付目标通过独立交付试验证明：由未参与 ZiZu 开发的实施工程师，在干净备用环境和模拟或真实协议设备上从零计时。全过程只允许使用公开文档、发布制品、解决方案包以及产品界面和公开 API。

出现以下任一情况即判定该次配置式交付失败：

- 修改平台源码；
- 直接操作数据库或执行临时 SQL；
- 使用未包含在公开交付流程中的一次性脚本；
- 依赖开发人员口头指导才能完成；
- 超过四小时或配置资产覆盖率低于 90%；
- 机器验收清单未全部通过。

## 开源边界

公开仓库包含平台核心、设备模板格式、光储充 EMS 参考配置、部署方案和验收测试。

具体客户参数、访问凭据、现场实际拓扑和商业服务不得进入公开仓库。

## Wayfinder 的目的地

形成一份可实施、可验收的 ZiZu 产品规格，明确配置资产模型、参考交付流程、运行安全边界、开源边界以及从当前 v0.4.77 到交付就绪版本的实现顺序。随后将规格拆分为带依赖关系的 tracer-bullet 实现票据。
