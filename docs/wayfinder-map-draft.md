## Decisions so far

- 首要使用者是实施工程师；业主操作员是已交付系统的运行用户。
- 光储充 EMS 首版覆盖设备接入、监控、历史、告警、手自动控制、基础策略、审计和部署运维。
- 配置式交付以无源码修改、四小时内、90% 资产通过模板与界面完成为验收门槛。
- 开源核心包含平台、配置格式、EMS 参考资产、部署和验收测试；现场私有数据不公开。
- 交付单位是版本化解决方案包，而不是零散模板。
- 首版采用单实例单站。
- 所有人工和自动控制使用统一控制命令入口。
- 解决方案包携带机器可执行验收清单并生成交付报告。
- 解决方案包采用声明式 Git 目录，以带版本的解决方案清单组合 YAML/JSON 资产，不使用数据库备份。
- 站点差异由强类型参数契约描述；敏感参数只引用运行时 Secret。
- 首版使用固定 EMS 运行工作台，解决方案包配置导航、分组、指标和趋势，不建设通用拖拽设计器。
- 解决方案包升级执行旧包、站点当前配置、新包的三方差异，保留站点覆盖并显式处理冲突。
- 实体定义与实体实例分离；规则、工作台、告警和控制统一引用站点内实体实例 ID。
- 必需实体绑定在安装/升级阶段确定；零候选或多候选阻止交付就绪，运行时禁止静默选源。
- 告警使用现场条件驱动的统一状态机；确认不等于恢复，人工不能伪造现场恢复。
- 所有写入创建统一控制命令，只有写后回读满足期望才算成功。
- 首版角色为 admin、engineer、operator；高风险控制可要求命令级二次确认。
- 生产模式业务 API 与 WebSocket 默认认证，仅最小存活探针匿名；开发匿名必须显式开启并警示。
- 平台以固定版本多架构镜像和 digest 发布，解决方案包独立语义版本，部署形成完整发布锁定。
- 四小时目标由未参与开发的实施工程师在干净环境中独立计时验证，源码、SQL、临时脚本和口头指导均判失败。

## Not yet specified

- 解决方案清单的具体字段、Schema 版本兼容性和签名机制。
- EMS 运行工作台的具体组件白名单和配置 Schema。
- 从现有数据库内模板迁移到解决方案包的兼容路径。
- 现有全局实体和多优先级绑定迁移到实例模型的规则。
- 现有三条告警处理链迁移到统一状态机的兼容方式。
- 现有四条写设备路径收口到控制命令的 API 兼容窗口。
- 现场离线部署和软件供应链验证。
- 首版策略集合及其仿真基线。
- 开源文档的信息架构与贡献者开发体验。

## Out of scope

- 首版计费与结算。
- 首版工单系统。
- 首版移动应用。
- 首版多租户与跨站集中管理。
- 首版通用拖拽大屏设计器，除非后续决策重新划定目的地。
