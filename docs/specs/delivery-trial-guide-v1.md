# ZiZu 交付试验向导 v1 规格

> 状态：规格已确认；尚未实现，不代表当前候选可用或交付就绪  
> 日期：2026-08-15

## Problem Statement

ZiZu 已有解决方案包、安装计划、实体实例、告警、统一控制、基础策略、审计、验收报告和不可变发布等能力，但“各能力存在”尚未形成实施工程师可完成的产品流程。当前交付页面仍要求人工填写自由 JSON、命令 UUID 和审计 UUID，权限拒绝证据甚至需要从 HTTP 响应头抄录；公开候选也没有一套开箱即用的干净环境和协议模拟器。开发测试可以通过，陌生实施工程师仍可能不知道下一步做什么、去哪完成、完成后平台是否已经取得有效证据。

因此，所有已实现能力都只视为待验证假设。可用性只能由未参与开发的实施工程师在干净环境中，仅使用公开制品、文档、解决方案包和产品界面完成四小时交付试验证明；架构是否合适也只能根据这条真实路径的摩擦、失败和证据缺口重新判断。

## Solution

ZiZu 提供平台维护的交付试验向导。实施工程师选择已验证解决方案后，向导以任务卡呈现强类型站点配置、绑定处理、安装审查、运行见证和报告封存，并持续显示已通过、待完成和阻断项。页面不要求理解内部表、自由 JSON、命令 ID、审计 ID或响应头。

向导不是控制或自动化引擎。人工控制、策略、告警确认和权限拒绝仍通过现有受保护产品操作发生；向导签发短期、不透明、不能授权的证据票据，产品在正常操作时隐式携带它，领域模块在成功或拒绝的不可变证据中记录关联。向导只观察这些证据并判断验收项是否满足，绝不为验收自行写设备、启用策略或确认告警。

公开试验套件提供固定发布制品、目标架构清单、隔离数据库与消息设施、协议模拟器、公开参考解决方案包和启动说明。最终仍由独立实施工程师通过产品界面完成试验；机器测试、合并、构建成功或开发人员演示均不能替代该证据。

## User Stories

1. 作为实施工程师，我希望从产品界面选择一个已验证的参考解决方案，以便从受支持的交付基线开始。
2. 作为实施工程师，我希望开始试验后看到唯一的当前阶段、完成进度和下一动作，以便无需询问开发人员。
3. 作为实施工程师，我希望每个任务使用业务名称和说明，以便不需要理解资源 UUID、数据库表或内部 API。
4. 作为实施工程师，我希望向导根据参数契约生成强类型表单，以便不填写自由 JSON。
5. 作为实施工程师，我希望 Secret 只选择引用且从不回显值，以便试验记录和报告不泄露凭据。
6. 作为实施工程师，我希望向导只展示当前设备目录中的受限绑定候选及匹配理由，以便安全解决缺失或歧义。
7. 作为实施工程师，我希望安装前看到可读的新增、修改、保留、删除候选、冲突和阻断摘要，以便理解实际影响。
8. 作为实施工程师，我希望过期计划或变化的设备目录明确阻断并告诉我重新规划，以便不会执行陈旧决定。
9. 作为实施工程师，我希望重复页面提交和网络重试保持幂等，以便不产生重复安装或证据。
10. 作为实施工程师，我希望安装后向导自动锁定安装和站点配置版本，以便后续证据属于同一交付基线。
11. 作为实施工程师，我希望向导自动检查发布锁、协议网关、绑定、实时数据和历史数据，以便不手工复制系统状态。
12. 作为实施工程师，我希望需要人工见证的任务能直接跳到相应产品页面，以便不在菜单中寻找功能。
13. 作为业主操作员，我希望手动控制仍经过权限、限值、联锁、冷却和高风险二次确认，以便试验不能降低现场安全。
14. 作为业主操作员，我希望控制只有回读确认后才被向导视为完成，以便接口成功不会冒充设备执行成功。
15. 作为业主操作员，我希望告警确认仍只表示知悉，现场恢复仍由观测驱动，以便试验不会伪造告警生命周期。
16. 作为实施工程师，我希望策略任务明确分成仿真、启用、执行一次、回读和停用，以便自动控制的每个阶段可见。
17. 作为实施工程师，我希望策略执行仍使用统一控制命令和既有限幅，以便向导不能形成自动控制旁路。
18. 作为实施工程师，我希望权限拒绝任务由产品自动关联拒绝审计，以便不从响应头抄录审计 UUID。
19. 作为实施工程师，我希望手动控制、策略控制和告警确认由产品自动关联证据，以便不填写命令映射 JSON。
20. 作为实施工程师，我希望证据缺失、过期、冲突或归属不唯一时看到稳定机器码和可执行修复建议，以便不能靠猜测通过。
21. 作为实施工程师，我希望刷新、退出登录或服务重启后继续同一次试验，以便现场工作可恢复。
22. 作为平台管理员，我希望试验锁定发布、包和验收清单摘要，以便中途升级不会混合证据。
23. 作为审计人员，我希望每项报告证据能追溯到主体、时间、安装、资产和不可变事件，以便结果可复核。
24. 作为客户，我希望报告封存后不可修改，以便交付结论能归档和签收。
25. 作为产品维护者，我希望试验记录每阶段耗时、人工步骤、阻断和配置覆盖率，以便用事实降低交付成本。
26. 作为产品维护者，我希望第一次试验失败仍完整保留，以便失败点进入下一轮产品改进而不是被隐藏。
27. 作为实施工程师，我希望公开试验套件一条命令启动隔离平台和协议模拟器，以便不依赖客户设备或开发环境。
28. 作为实施工程师，我希望公开试验套件拒绝 `latest`、架构不符、摘要不符和缺失迁移，以便试验输入可重现。
29. 作为产品维护者，我希望由未参与开发的人只用公开界面完成全部任务，以便真正证明产品可用。
30. 作为产品维护者，我希望只有八项能力、必需报告项、四小时和至少 90% 配置覆盖率同时满足时才称为交付就绪。

## Implementation Decisions

- 交付试验是持久产品对象，拥有稳定 ID、revision、阶段、锁定基线、任务状态、证据关联、耗时和最终报告引用。
- 公开协调接口保持很小：开始试验、读取/刷新试验、封存报告。不存在代替所有领域操作的通用 `act` 接口。
- 开始时锁定发布锁、解决方案包摘要和验收清单摘要；安装成功后锁定安装 ID 与站点配置版本。任一锁定对象变化都使相关任务阻断，不能静默切换。
- 任务由平台支持的固定验收种类编译而成。解决方案包不能声明脚本、URL、任意前端代码或通用流程图。
- 任务卡只返回平台拥有的展示数据、强类型输入和跳转意图；前端按固定意图路由，不执行包提供的 URL。
- 证据票据绑定试验、任务、主体、安装或包基线、允许的证据种类和短时间窗。它不包含权限，也不能绕过任何领域校验。
- 控制、策略、告警和授权模块仍是各自行为与安全不变量的唯一所有者。它们只在已有不可变事件中附加试验关联；交付试验向导没有设备写 Adapter。
- 验收只读取已发生证据。手动控制必须达到回读确认；策略必须有仿真、显式启用、统一命令回读和停用证据；告警必须有触发、真实主体确认和现场恢复；权限拒绝必须来自真实授权判断。
- 证据匹配同时校验试验基线、安装、资产、主体、时间窗和任务。零匹配为待完成，多匹配或不一致为明确错误，禁止按时间最近或查询顺序猜测。
- 试验报告沿用不可变交付报告，但由向导封存并包含试验耗时、人工步骤、阻断、配置覆盖率和锁定基线。
- PostgreSQL 是模块内部可替换持久化 Adapter；身份、交付、实体、告警、策略和控制是进程内协作者；Neuron 或公开协议模拟器是唯一真实外部设备边界。
- 干净环境试验套件与生产部署分离。它只连接公开模拟设备、使用固定摘要并生成试验 release lock，绝不包含客户拓扑或凭据。
- 当前候选只有在独立人工试验通过后才能提升为交付就绪版本；自动测试只作为回归与失败定位证据。

## Testing Decisions

- 唯一主测试缝保持为公开端到端交付：从干净环境和固定制品开始，经产品界面或同等公开 HTTP 边界完成解决方案选择、配置、绑定、安装、协议观测、告警、手动控制、策略、审计，到不可变交付报告结束。
- 协议模拟器是设备边界测试 Adapter；测试不得直接写遥测、命令、告警、审计或试验数据库表。
- 第一条 tracer bullet 证明：开始试验后获得可读任务卡；实施工程师通过现有产品控制入口完成一次回读确认；向导自动把证据归入正确任务；页面和请求均不要求命令 UUID 或映射 JSON。
- 后续纵向切片依次覆盖参数与安装、告警见证、策略见证、权限拒绝、发布锁和最终报告；每个切片都必须从公开身份和产品/HTTP 边界开始并产生可见进度。
- 辅助状态测试只断言试验阶段、revision、证据零/一/多匹配和报告不可变性，不断言 SQL、私有函数或内部调用顺序。
- 公开权限测试证明 admin、engineer、operator 只能执行各自既有领域动作；持有证据票据不能提升权限。
- PostgreSQL/Uvicorn 主缝证明重启后试验、证据关联和封存报告仍可读取，并证明并发刷新、重复操作和过期 revision 的确定结果。
- 前端在不新增测试依赖的前提下先以生产构建、静态无自由 JSON/人工 ID 门禁和人工浏览器主流程验证；是否增加最小浏览器自动化由独立票据决定。
- 最终验收必须由未参与开发的实施工程师执行四小时干净环境试验。开发人员或代理自行操作只能算预演，不能作为通过证据。

## Out of Scope

- 通用 BPM、拖拽工作流、包内脚本或任意审批引擎。
- 由向导直接下发控制、启用策略、确认告警或代替身份授权。
- 以证据票据替代 Bearer 身份、能力、二次确认、联锁、冷却或策略授权。
- 多站点、多租户、跨站试验编排和客户生产拓扑。
- 为了让试验通过而放宽现有控制、告警、策略、审计或发布门禁。
- 把开发测试、模拟数据库写入、合并记录或成功构建当作独立交付试验。

## Further Notes

- 本规格深化既有配置式交付主缝，不取代解决方案包、统一告警、统一控制或不可变发布 ADR。
- v0.4.79-rc.1 只是可核验候选制品，不是本规格的完成证据。
- 若独立试验发现当前领域接口无法提供无歧义证据，应优先修正领域边界，而不是在向导中增加猜测或例外。
