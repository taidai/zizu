## 根因与修复

- 节点接口本身约 `0.2s`，并非后端或数据库瓶颈。旧前端却在首屏强制下载 Monaco、GoRules、WASM
  和一个 `3.18MB` 的公共依赖包；进入节点页时又提前加载历史图表和实体加工工作区。因此接口要等页面
  大包下载后才会发起，形成“节点管理加载慢”的直接症状。
- v0.6.3 删除全站入口对规则编辑器的预加载，并取消把全部第三方依赖强塞进一个公共包的打包规则。
  规则编辑器仅在进入“规则引擎”时加载，原始点位历史图表仅在点击“历史”时加载，实体加工工作区仅在
  点击“标准实体”时加载。节点 CRUD、L0/L1/L2 语义和后端接口均未改变。
- 新增加载边界回归测试，禁止首屏重新直接依赖 Monaco/GoRules，并要求历史图表和实体工作区保持按需加载。

## 切换与回退

- 只重建 Compose `backend`；TimescaleDB、NanoMQ、Neuron 均未重启。
- 保持 `network_mode: host`、`tmpfs: /dev/mqueue`、`unless-stopped` 和既有运行环境。
- 本轮没有 Schema 变化，未重复制作数据库完整备份；切换前运行配置保存为
  `/opt/zizu-release-test-0.5.0/release.env.pre-v0.6.3-840e42b-20260901-075013`。需要回退时恢复该文件并
  重建 backend。

## 验收证据

- 同一公网、同一冷浏览器计时：首屏 DOM 从 `11.631s` 降至 `0.419s`，登录后应用可用从 `13.453s`
  降至 `2.170s`，节点管理骨架从 `2.917s` 降至 `0.231s`；节点接口约 `0.319s` 返回，L0 快照等数据
  最迟约 `1.041s` 到齐。节点页加载期间没有 Monaco、GoRules、WASM 或编辑器 worker 请求。
- 无头浏览器逐项打开原始实时、原始历史、标准实体和规则引擎，全部可见；历史图表和实体工作区按需加载。
  本轮是纯加载优化，没有执行控制、设备写、自动策略或写入式全量 E2E。
- `python scripts/verify_delivery.py --site-url http://e606.hlszh.com:9000` 返回 `PASSED`、`missing=[]`：
  后端 406 项通过（160 项环境跳过）、脚本 51 项、前端 56 项、生产构建及公网站点检查全部通过。
- backend 运行固定摘要，`healthy`、restart 0、host 网络、`/dev/mqueue` tmpfs 均确认；启动后日志无
  ERROR、Traceback 或迁移失败。

## 现场边界

- 规则引擎首次进入仍需下载约 `6.6MB` 的专用编辑器代码，现场测得约 `9.7s`；它已不再拖慢登录、节点
  管理、告警或 EMS 页面。若下一轮继续做性能优化，应单独缩小规则编辑器包，不要恢复全站预加载。
- 公网仍使用 HTTP，未启动 Caddy/TLS；development 不安全凭据告警仍在，不能宣称为公网生产安全配置。
