# 自足IOT 红金亮银正式界面：首批交付规格

日期：2026-09-07。状态：首批范围 A 已获用户确认；本书面规格待核对。

## 1. 交付目标与范围

把已认可的本机 Demo 设计迁入正式系统，交付新版外观、真实运行首页和节点/点位/实体操作主干，通过验证后发布到1号机。实施工程师配置真实数据，业主操作员看现场结果；不把 Demo 的内存保存或模拟控制当成正式功能。

本次选择分批迁入，不选择所有 Demo 页面全部改完才发布。告警、调度、控制与系统工具同步样式、沿用现有正式流程；独立设备卡片页面与新的单张 JDM 表格编辑体验留到后续。既有功能入口不得因本次改版丢失。

## 2. 界面与使用路径

- 品牌为“自足IOT”，运行页标题为“光储充现场”。沿用已确认深红、暖金、亮银及 Noto Sans SC 字体栈；保留正常/故障等独立状态色，字体缺失时使用既有中文回退，不新增字体下载依赖。
- 登录默认进入运行首页。页头提供工程配置入口，日常导航与配置操作分组；这是同一应用，不新增运行模式、账户体系或权限。操作员不因新入口获得配置权限。
- 首批运行区保留运行总览、现有只读运行监控、告警和现有授权控制入口。调度编辑仍按既有角色限制进入；不向操作员直接开放包含发布、启停、清锁的配置页。
- 工程配置按“节点与数据 / 告警与调度 / 系统工具”归类。左侧只显示真实节点；右侧为原始数据与标准实体两种视图。L1 从选点后的“加工为实体”或实体“数据来源与计算”进入，不新增第三种树节点或独立层级。
- 原始数据与实体都能看实时、历史、质量和来源；保留节点维护、导入预览、点位维护、模板管理、加工检查/发布/停用等真实能力。表单适合时放入弹窗，但不简化已有发布确认、摘要、冲突或未知结果处理。
- 以1280×800横屏验收十行表格的可用空间，并检查1024×768。数据不足十条按实际数量显示，不填假记录；较小屏允许内容滚动，导航、弹窗确认与取消始终可达，主要触控按钮至少44px。

## 3. 真实数据与刷新

唯一主干保持为：真实节点树、L0原始点位、L1点位加工、L2全局实体，再供告警、调度、控制与运行首页使用。L0保持协议事实，跨节点加工仍只读其他节点的L2；不改Schema、采集、公式引擎或控制协议。

首页复用正式实体目录和已提交L2观测，以 `entity_instance_id` 关联，并展示所属节点、业务标识、单位、质量与时间。修正现有工作台按旧camelCase键和首个匹配实体取KPI的展示缺陷：不得通过名称猜测绑定，不重命名存量实体，不把单设备值当站级总值。

- 首页业务区展示来源明确的实体卡片；单设备指标必须带设备名。同定义存在多设备时分别标明来源，不静默取第一台、不在前端求和或平均SOC。
- 只有实际存在且身份明确的站级L2才展示站级汇总。缺少对应配置显示“未配置”和工程入口，不能用零或演示数值补齐；本轮不自动创建站级公式或修改现场实体。
- 不迁入 Demo 固定能流箭头、固定功率方向与策略目标。没有已定义的方向依据就不显示方向；首页缺汇总不代表整个光储充站点交付完成。
- 复用提交帧实时客户端与投影：先获取一致快照，随后按游标处理增量；断流或游标失效后按现有机制重取快照。按活动页面管理订阅，不给每张卡片另建数据库轮询；页面切换取消旧请求，旧响应不得覆盖新选择。
- 只有现有观测接口确实提供最后值时才显示“最后值”。非GOOD、超时、断线、读取失败分开提示，不放宽原质量或时效门槛，不把HTTP成功、MQTT连接或旧GOOD值当成当前正常。使用既有实时证据补齐工作台显示，不另建一套时效判定规则。
- 历史按所选实体按需读取，单位与身份不变；不同实体或单位不拼成一条折线，非数值实体不绘制伪数值趋势。

## 4. 实现边界与失败处理

正式入口为 `frontend/src/App.tsx`，而不是 `frontend/demo-tablet`。迁入样式、视觉组件与布局，保留正式认证、会话恢复、退出、角色校验及前后端版本显示。Demo角色切换、数据场景、故障注入、重置和模拟回读不得出现在正式构建。

复用 `NodeTreePage`、`DataTrunkWorkspace`、原始点位/历史、`InlinePointProcessingPanel`、模板和实体观测组件；首页数据适配在工作台页及其已有服务边界内完成。仅按需要补充展示所需的既有L2证据，不新增数据库表、万能配置层或第二套实时接口。

告警复用事件、规则、HTTP通知组件；调度保留完整JDM模型、保存/试算/发布/启停/清锁；控制保留二次确认、幂等、服务端门禁与新L2回读。换导航或关闭弹窗不执行这些操作，接口受理不显示为设备成功。发现既有故障阻断本次验收时记录并聚焦修复，不靠放宽门禁或假成功绕过。

新建加工草稿与明确的所选来源关联；编辑指向明确实体，重复业务标识不能隐式覆盖。保存失败/未知结果保持正式恢复机制；取消、换节点、切页不能将上一对象草稿误用于下一对象。告警翻页选择范围必须明确，不能形成不可见批量操作。

## 5. 验收证据

发布前使用正式前后端及隔离数据测试，不复用 Demo 的通过记录：

1. 新导航、三角色、退出及1280/1024横屏；翻页、弹窗和10行表格可用；浏览器刷新后已保存配置仍存在。
2. 节点→导入预览→L0实时/历史→加工检查/发布→同身份L2实时/历史/来源→告警选实体。测试新增数据局限于隔离测试根节点，结束清理本次资源。
3. 首页无需刷新能收到新提交值；两个节点同业务标识不串值；缺配置不显示0；GOOD但超时、坏质量、断流与恢复分别验证；历史不混单位、不连假曲线。
4. 现有告警及调度模型/接口回归；切导航不发布、启用、清锁、发送通知或写设备。真实控制闭环测试不包含在本次UI发布授权内，使用已有无现场副作用的测试边界。
5. 按仓库门禁运行后端、脚本、前端模型测试及正式 `npm run build`，运行节点无头主干和本次首页专项；如实区分通过、失败与条件跳过。修复期间先跑受影响测试，发布前再跑完整门禁，不重复堆叠无意义等待。

验收记录包含源码提交、版本、Schema、构建制品和检查结果。没有真实数据证据或任一必需检查缺失，结果为INCOMPLETE；执行失败为FAILED，不能用页面能打开替代功能通过。

## 6. 发布与回退

沿既有固定ARM64镜像流程发布，版本按当前版本递增并在发布前复核。先核对1号机实际版本、容器、磁盘、在途控制及部署文件，备份当前配置与发布文件并验证隔离恢复，记录上一固定镜像摘要；不复用过时文档中的回滚参数。

只替换既有应用服务，保持host网络、`/dev/mqueue` tmpfs、挂载、HTTP方式及数据库/MQTT/Neuron；不申请TLS、不清数据、不自动启用策略或重试设备命令。存在会受重启影响的在途控制时停止切换并报告，不能擅自终止或重发。

部署后登录1号机，以无头浏览器沿主干只读复验，并核对首页真实数据/持续更新、版本及新增错误。无头失败才用可见浏览器定位；本次UI里程碑再做一次可见抽查。失败时恢复上一应用固定制品，不覆盖用户发布后新配置；本版不做Schema迁移。

书面规格确认后形成短实施计划，再进入开发与部署。本机Demo继续保留用于对照，不作为现场发布入口。
