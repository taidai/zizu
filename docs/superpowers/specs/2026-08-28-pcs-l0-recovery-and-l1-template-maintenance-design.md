# PCS L0 恢复与 L1 模板维护设计

**状态：Accepted**

## 目标

修复 1 号机 PCS 原始点位空白，并让平台管理员可以在现有点位加工页面中复制、修改、检查和发布共享模板。实施工程师继续只负责为当前设备选择模板、绑定原始点位、检查并应用。

## L0 修复边界

1. Neuron 中 PCS 各订阅组统一发布到 ZiZu 已监听的 `neuron/en9_pcs/telemetry`。
2. 过期的 PROCESSING 帧被新处理器接管时保留原 attempt count，只更换 owner、token 和固定租约；年龄超过 60 秒仍按既有预算终结，避免队首永久阻塞。
3. committed snapshot 对迁移前 `frame_sequence=0` 的旧 L0 允许从实际非空类型列读取最后值，同时一律显示 STALE；新帧继续严格执行声明类型，不能用兼容读取掩盖新的类型错误。
4. 当前无新采样时显示最后值、数据时间和“超时”，不显示空白，也不标成正常。

## L1 用户路径

管理员在点位加工页展开“维护共享模板”，选择一个现有修订后执行：

`复制模板 → 修改品牌/型号/输入契约/输出加工 → 检查 → 发布新版本`

- 模板修订不可变；同一模板修改时 revision 自动加一，新模板从 revision 1 开始。
- 首版编辑现有输入和输出，不在线创建业务实体定义，不引入自由脚本。
- 加工类型只提供直通、倍率/偏移、枚举、公式四种表单；底层仍生成现有单 JSON 模板并复用现有解析器。
- 检查接口零持久化，返回规范化摘要和内容摘要；发布复用 import 接口。
- import 与 validate 只允许管理员；工程师可以读取和导出模板，以便诊断和交付，但不能改共享目录。
- export 必须经过真实认证授权，不能只写 OpenAPI 元数据。

## 不做

- 不增加表、第二套模板模型、审批流、模板市场、设备模板或解决方案包。
- 不允许原地覆盖已发布修订。
- 不把当前节点的现场 UUID 绑定写入共享模板。
- 不重做节点页视觉系统；沿用当前工业工作台样式。

## 验收

- 1 号机数据帧队首不再报 `DATA_FRAME_CLAIM_FAILED`，积压最终归零。
- PCS MQTT 新消息进入 ZiZu；PCS 原始点位显示数值、时间和正确质量。
- 无新数据时仍显示最后值并明确标记“超时”。
- 工程师无法检查或发布共享模板；管理员可复制现有模板、修改四类加工、检查并发布新修订。
- 新修订出现在模板列表，可继续走现有“绑定 → 检查 → 应用”路径。
