# ZiZu 配置型工业 IoT 平台核心架构总纲

**状态：** 已确认（Accepted）
**日期：** 2026-08-27
**参考场景：** 光伏、储能、充电桩、并网与负荷组成的单站 EMS

## 1. 文档权威与产品目标

本总纲是 ZiZu 唯一的总体架构入口，负责把已确认决策汇成一张无冲突总图。专项规格只解释某一部分
怎样实现；与总纲冲突的历史术语、数据流和产品层级，均以总纲及其引用的最新 ADR 为准。

ZiZu 的目标是成为一套**用于开发和交付 EMS 的配置型工业 IoT 平台**：实施工程师在不修改平台源码、
不直接写 SQL 的前提下，把不同品牌设备接入统一节点树，通过点位加工形成稳定业务实体，再配置告警、
JDM、控制和固定 EMS 工作台，完成可运行、可追溯、可恢复的工业控制系统。

光储充 EMS 是首个参考交付，但核心模型不绑定某个 PCS 品牌、协议或现场拓扑。

## 2. 一句话架构

```text
真实节点树 → L0 原始点位 → L1 点位加工 → L2 全局实体 → 告警 / JDM / 控制 / 固定 EMS 工作台
```

节点树组织现场，L0 保存协议事实，L1 消除品牌差异并完成安全计算，L2 向所有上层应用提供稳定业务
语义；实时黑板和数据帧负责让这条主干按统一节拍、一致且可恢复地运行。

## 4. 领域骨架

### 4.1 节点

节点只表达真实站点、能源子系统、设备或确有业务归属的逻辑对象。节点具有稳定身份、类型、父子关系和
显示名称，并直接承载 L0 目录、已安装 L1 和 L2 实体；平台不再增加“设备实例”中间层。

### 4.2 L0 原始点位

L0 是协议网关从实际设备取得的品牌相关事实，包含来源键、强类型值、单位、质量、设备时间、接收时间
和源顺序。L0 只供点位诊断和本节点 L1 使用；跨节点加工、告警、JDM、控制和业务画面不得直接读取
其他节点或品牌 L0。

### 4.3 L1 点位加工

L1 是挂载在输出所属节点上的版本化配置，负责品牌字段映射、单位换算、枚举与状态解析、字符串多码
故障映射、多点组合、质量与时间处理，以及强类型复杂公式。

- 同节点加工可以读取本节点 L0；
- 跨节点加工只能读取其他节点已经标准化的 L2；
- 全站依赖编译为强类型、单位可验证的有向无环图；
- 禁止循环、运行时猜测来源和任意 Python/JavaScript；
- L1 只保存模板、不可变修订、输入输出、规则、确定绑定、当前安装和审计，不保存普通中间时序值。

### 4.4 L2 全局实体

L2 是上层应用唯一稳定的数据接口。每个实体直接属于一个节点，以稳定 UUID 和业务语义键标识，并
携带强类型值、单位、质量、时间戳、配置与加工修订及来源证据。更换设备品牌、协议地址或 L1 修订时，
只改变输入绑定，不改变 L2 身份和上层引用。

“全局”只表示在一个站内被所有上层模块统一引用，不表示跨站、多租户或全局变量。

统计结果仍属于 L2，不新增 L3。当前窗口可使用可恢复运行投影，封窗或显式修正后形成不可变 L2 历史
修订；统计加工产生的 L2 及任何 `control_eligible=false` 的依赖链不得进入自动控制。这是保留的目标语义，旧的
独立业务指标模板、投影和能力契约表已经被 Schema 044 硬切删除，当前尚未按新主干重新实现。

## 5. 唯一配置交付路径

点位加工模板是唯一设备语义复用资产，使用一个规范 JSON 文件描述明确设备类别、品牌型号或系统计算
场景的强类型输入、L2 输出、规则、单位和质量策略。模板不携带现场凭据、节点 UUID、客户拓扑、页面、
脚本或解决方案安装信息。

```text
建立真实节点
  → 配置协议连接并看见 L0
  → 选择或导入单文件点位加工模板
  → 自动匹配本节点 L0 / 显式选择跨节点 L2
  → 处理缺失、歧义、类型、单位和循环阻断
  → 预览 L0 → L1 → L2
  → 原子发布并递增内部配置修订号
  → 查看 L0/L2 实时、历史与来源完成就地验证
```

预览不改变运行态。发布时必须重新复核模板摘要、输入绑定、DAG 和基础配置修订号；任一阻断或并发
变化都使整次发布零写入。成功发布在同一事务内写业务配置、不可变修订和追加式审计，幂等重放返回
原结果。

配置切换还必须先暂停旧修订拍照并排空旧帧与未发布 outbox。新修订进入 WARMING，只有全部必需 L0
收到本轮新样本后才可生成首帧；旧修订结果和已排队控制意图不得继续驱动业务。

## 7. 实时数据流

1. 新样本按可信源序号、可信设备时间或平台接收次序判断新旧；重复、乱序和迟到样本直接丢弃。
2. 同一点位在一个节拍内只保留最后一条新样本；值相同但时间或顺序更新仍算新样本。
3. 每站一个默认 1 秒的统一节拍；黑板未变化不拍照、不写数据库。
4. 启动、重启或配置切换后，活动 L1 依赖的全部必需 L0 都收到本轮新样本才进入 READY。
5. 连续三拍没有新样本时保留最后已知值，但质量转为 STALE；机器消费者必须按质量 fail closed。
6. 有新样本或质量变化时冻结完整不可变数据帧；冻结后的更新进入下一帧。
7. 事务 A 先保存 PENDING 帧和本拍变化 L0，确保后续失败也不丢已经提交的原始事实。
8. 帧按固定配置修订对全部即时 L1 运行一次强类型 DAG；窗口统计继续走独立 L2 运行投影。
9. 事务 B 原子推进可见 L0 latest，保存 L2 历史/latest、来源证据和统一帧 outbox，并终结 COMPLETE。
10. 数据库提交后，点位页消费 committed L0，告警、JDM、控制、工作台和业务画面只消费 committed L2。

```text
异步样本 → 黑板标脏 → 到节拍冻结完整帧
                         │
                         ├─ 事务 A：frame + 变化 L0 → PENDING
                         │
                         ├─ 固定修订的完整 L1 DAG
                         │
                         └─ 事务 B：L0 latest + L2 + 来源 + outbox → COMPLETE
                                                                    │
                                                                    └→ 提交后通知
```

帧处理最多尝试 3 次且总年龄不超过 60 秒。超限后保留 L0、终结 FAILED、产生系统告警，并把失败输出
及其全部 DAG 下游 L2 转为 STALE；无法定位失败源时全部活动 L2 fail closed，然后继续处理后续帧。

## 8. 最小数据结构

全站只使用共享关系表和共享时序表，不按节点、设备、品牌、L0/L1/L2 分表。

| 数据对象 | 唯一职责 |
|---|---|
| 节点与 L0 目录 | 真实树结构、协议来源键、类型、单位与采集元数据 |
| 点位加工模板与不可变修订 | 可复用 L1 定义及规范内容摘要 |
| L1 输入、输出、规则与绑定 | 强类型 DAG、确定来源与当前安装 |
| L2 实体 | `node_id + definition_key` 的稳定站内业务身份 |
| 配置修订与审计 | 原子发布顺序、操作者、前后摘要、结果和时间 |
| `t_data_frames` | 帧序号、拍号、配置修订、状态、租约、失败与完成时间 |
| `t_telemetry` / latest | 共享 L0 历史和最新终态可见值 |
| `t_l2_observations` / latest | 共享 L2 历史和最新终态业务事实 |
| L2 来源关系 | L2 到实际 L0 观测、加工修订与来源摘要的证据 |
| `t_data_frame_outbox` | 每个 COMPLETE/FAILED 终态帧一条的提交后通知 |
| 统计运行投影与结果修订 | 当前窗口暂定值和不可变完成/修正事实 |
| 防重复缓存 | 只拒绝近期重复，不承担历史与永久来源证据 |

L1 不建立普通时序表，也不保存整帧大 JSON。L0 历史只保存本拍真正到达的每点最后样本；L2 随每个
变化帧保存活动输出。新主干的 L0/L2 latest 统一按 `frame_sequence` 推进，业务时间只用于显示、追溯
和统计，不能让旧帧倒退可见状态。

## 9. 上层模块边界

| 模块 | 职责 | 硬边界 |
|---|---|---|
| 点位诊断 | 查看 L0 实时、历史、质量和来源 | 不作为业务控制输入 |
| 告警配置/中心 | 对 L2 批量指定实体、等级、触发/恢复条件和字符串多码映射 | 确认不等于恢复；不得直接读 L0 |
| JDM | 以版本化决策模型产生判断或控制意图，试运行与正式执行使用同一模型 | 是唯一上层规则语义；不得成为 L1 公式引擎 |
| 控制 | 把人工或 JDM 意图转换为统一可审计命令 | 权限、质量、活动修订、限值、联锁、幂等和写后回读全部通过才写设备 |
| 固定 EMS 工作台 | 按节点类型和 L2 标准语义展示能流、SOC、功率、可用性、趋势和告警 | 不提供通用页面设计器，不建立第二套业务数据 |

告警、JDM、控制和工作台只能通过稳定 L2 seam 获取数据。任何统计加工结果、STALE/BAD 值、旧配置修订
或来源链不具备控制资格时，自动控制必须拒绝。

控制是唯一允许的反向链路。人工操作或 JDM 只向可控 L2 实体提交意图；统一控制服务通过已确认的
控制绑定找到唯一可写 L0 点位，经 Neuron 下发后，再等待正常采集链把现场状态重新送回 L2 完成回读：

```text
操作员 / JDM → 统一控制命令 → 可控 L2 → 唯一 L0 写点 → Neuron → 设备
                                                          │
                    回读确认 ← committed L2 ← L1 ← 新 L0 ←┘
```

“接口返回成功”不等于控制成功，只有期望 L2 在容差与超时内由新现场观测确认，命令才可完成。

## 10. 产品界面功能清单

主导航只保留：

- EMS 工作台；
- 节点与数据；
- 告警中心与告警配置；
- JDM；
- 控制；
- 系统工具。

“节点与数据”左侧为真实节点树，右侧围绕所选节点固定展示：

- **L0 原始点位**：实时值、质量、数据时间、接收时间、来源、搜索与历史趋势；
- **L1 点位加工**：模板选择/导入/导出、输入匹配、映射与强类型公式、阻断、预览、发布和当前修订；
- **L2 全局实体**：实时值、质量、时间、历史、来源证据及告警/JDM/控制/画面消费者；
- 顶部数据链状态：`采集 → L0 → L1 → L2 → 上层应用`，明确 WARMING、READY、STALE 和失败位置。

实时页面首次打开或断线重连时，用 REST 获取一份完整最新终态快照和帧游标；之后只接收 WebSocket
提交后帧增量。游标过旧时明确要求重读，不持续轮询 latest 数据库表。

删除“解决方案交付”、独立“设备模板”、独立“实体管理”和自由大屏设计器入口。

## 11. 安全、质量与失败原则

- **强类型**：配置发布前验证值类型、单位、方向和公式输出；不依赖运行时碰运气。
- **确定绑定**：零候选或多候选都阻断；不按名称相似度、创建顺序或优先级静默选择。
- **质量优先**：GOOD/UNCERTAIN/BAD/STALE 与最后值分别表达；非 GOOD 不得因数值非空而进入控制。
- **提交后可见**：数据库未提交时不推送、不告警、不执行 JDM、不控制。
- **稳定身份**：品牌替换、模板升级和地址变化不得改变 L2 UUID 或上层引用。
- **配置栅栏**：新配置发布前排空旧帧/outbox；写设备前再次复核来源帧属于活动配置修订。
- **来源证据**：每个 L2 能追到实际 L0 观测、L1 修订、配置修订、质量和时间依据。
- **硬切迁移**：不保留旧 API、兼容表、双写或运行期 fallback；部署前完整备份并验证隔离恢复。
- **唯一控制入口**：人工和 JDM 都产生同一种控制命令，并留下权限、限值、联锁、下发和回读审计。

## 12. 当前实现与目标差距

以下状态是对源码提交 `a3e20a2` / v0.4.85-rc.9 / Schema 048 的只读盘点；该版本已经部署 1 号机，
但不代表目标架构已经全部完成。

| 范围 | 当前状态 | 主要差距 |
|---|---|---|
| L0 采集、历史与 latest | 已实现 | 已按帧序推进并只在终态提交后对节点页可见 |
| L1 模板、确定绑定与跨节点 DAG | 已实现主链 | 已完成点位加工、Schema 044 节点硬切和电表纵向切片；继续增加真实模板须服从实际交付需求 |
| L2 历史、latest、来源与统一 outbox | 已实现 | 上层状态型消费者尚未接入统一 outbox |
| 固定 EMS 工作台 | 部分实现 | 固定页面存在，仍需改为只消费 committed frame L2 |
| 真实节点树硬切 | 已实现主链 | 继续清理不在公开主线上的历史命名和只读档案入口 |
| 删除解决方案与设备实例 | 已实现主链 | Schema 与主导航已硬切；历史文档只作演进记录 |
| L0/L2 实时界面 | 已实现 | 已使用一次快照、帧游标和统一 WebSocket 增量，旧双流已删除 |
| 告警 | 部分实现 | 配置与运行存在，尚未统一到 committed frame L2 seam |
| JDM | 部分实现 | 编辑与执行存在，尚未完成活动配置修订和帧消费门禁 |
| 统一控制 | 部分实现 | 命令/绑定存在，尚未完成来源帧与活动修订的写前重验 |
| 配置修订与审计 | 部分实现 | L1 已接入，告警/JDM/控制与配置-拍照栅栏尚未全部统一 |
| 统计加工与时间能力契约 | 未实现（目标语义保留） | Schema 044 已删除旧业务指标模板/投影/窗口表；以后只能作为明确 L1 规则类型和普通 L2 结果重新交付，不建立独立统计实体系统 |
| 实时黑板、统一节拍和数据帧两段事务 | 已实现 | 继续以故障注入和 1 号机运行证据巩固，不建立第二条运行链 |

因此当前准确表述是：“L0→L1→L2、实时黑板、数据帧和节点实时界面主链已经实现并部署；告警、JDM、
控制和固定 EMS 工作台仍需逐个收口到同一 committed L2 seam，随后完成真实光储充参考交付。”不得
因数据帧和单个电表切片通过，就宣称整个平台已经交付就绪。

## 13. 简单配置交付闭环

```text
建站点和设备节点
   → 配协议连接
   → 看见 L0
   → 选点位加工模板并自动匹配
   → 处理少量阻断
   → 预览并原子发布
   → 看见稳定 L2、历史和来源
   → 批量配置告警 / JDM / 控制 / EMS 工作台
   → 模块内试运行与回读验证
   → 固定版本、Schema、模板摘要和配置修订后交付
```

总架构完成必须以一条真实光储充 EMS 纵向闭环证明：

1. 实施工程师只使用公开界面、模板和文档，不修改源码、SQL 或模板正文；
2. 新建光伏、储能、充电、并网和负荷节点并接入至少一类真实或协议模拟设备；
3. L0、L1、L2 的实时、历史、质量、时间和来源能够逐层下钻；
4. 更换同类设备品牌只替换 L1 模板与输入绑定，L2 UUID 及上层引用不变；
5. 告警、JDM、手动控制和工作台只引用 committed L2；自动控制继续通过安全门禁和回读；
6. 重复、迟到、STALE、事务失败、进程重启和配置并发均产生确定结果，不出现半帧、假 GOOD 或倒退；
7. 发布锁定平台版本、镜像摘要、Schema、模板摘要和配置修订，备份与回退经过验证；
8. 未参与开发的实施工程师能够在约定时间内独立重复完成并留下机器可核对证据。

## 14. 分阶段开发顺序

本总纲是长期北极星，不作为一个超大重构任务。后续按四个可独立验收的纵向计划推进：

1. **数据帧底座（已完成）**：实时黑板、统一节拍、帧 Schema、事务 A/B、恢复、失败和统一 outbox；
2. **实时界面（已完成）**：L0/L2 完整终态快照、帧游标、WebSocket 增量和节点数据链状态；
3. **上层收口（当前）**：告警、JDM、控制和工作台只消费 committed L2，补活动修订与控制写前门禁；
4. **EMS 参考验收**：完成光储充配置闭环、品牌替换、重启恢复、性能、发布锁定和独立交付试验。

每一阶段都必须先写独立规格/计划，以公共 seam 做 TDD，并在验收后再进入下一阶段；不同时铺开所有
页面、设备和模板。

## 15. 明确不做

- 不做解决方案包、解决方案安装、设备实例、项目空间、多租户或站点复制；
- 不做独立设备模板，品牌适配统一进入点位加工模板；
- 不做万能表达式、任意脚本、第二套规则引擎、通用工作流或自由页面设计器；
- 不为节点、设备、品牌、L1 中间值或 L0/L1/L2 分别建立超级表；
- 不让告警、JDM、控制和业务画面绕过 L2；
- 不引入 Redis、Kafka、新微服务、逐点节拍或 active-active backend；
- 不保留已删除概念的兼容 API、兼容表、双写和运行时 fallback；
- 不把现场凭据、客户参数和真实拓扑写入公开模板或仓库；
- 不把“页面可打开”当作工业系统已经交付。

## 17. 开发聚焦语句

后续所有开发都必须服务于同一条主线：**实施工程师在真实节点树中接入 L0，通过可复用、强类型、
可预览并原子发布的 L1 点位加工形成稳定 L2；单站实时黑板按统一节拍冻结可恢复数据帧，数据库提交
后，告警、JDM、控制和固定 EMS 工作台只消费带质量、时间和来源证据的 L2，从而无需修改源码或 SQL
即可完成光储充 EMS 的配置、验证和交付。**不能直接缩短这条闭环的功能不进入当前主线。
