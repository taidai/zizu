# 节点管理无头浏览器验收设计

## 目标

用一套五分钟内完成的 Playwright 无头浏览器测试，沿着“真实节点树 → L0 原始点位 → L1 点位加工 → L2 全局实体”验证节点管理现有功能确实可用。测试报告必须明确给出通过、失败、耗时和失败证据，禁止仅凭接口返回成功判定页面可交付。

## 边界

- 测试目标为 1 号机已部署站点，默认地址由 `ZIZU_E2E_BASE_URL` 提供。
- 用户名、密码和其他秘密只从进程环境读取，不写入仓库、报告、截图名称或日志。
- 所有平台写操作只发生在专用根节点 `E2E验证` 及本次运行创建的临时子节点内。
- 真实 PCS、电表、BMS 等节点只允许读取；测试不得下发控制，不得启用或执行规则。
- E2E 使用独立的模拟 Neuron 节点、采集组、点位和 MQTT 来源，不复用真实点位的 `source_path`。
- 测试结束通过正常“退役”流程处理临时平台节点，保留审计、历史和来源证据；模拟 Neuron 资源可在测试后删除，避免污染网关目录。

## 用户旅程

1. 登录并确认节点管理页面可达。
2. 在 `E2E验证` 下新建临时设备节点，完成编辑、搜索、刷新、选择。
3. 创建独立模拟 Neuron 目录，通过页面完成点位导入预览、确认和结果核对。
4. 发布确定值的模拟 MQTT 数据，确认 L0 实时值、质量、时间、来源可见，再确认历史查询、搜索、类型筛选和分页可用。
5. 在点位加工页选择 L0 输入，检查加工结果并发布 L2 实体。
6. 创建共享点位加工模板，完成检查、发布、选择和安装；模板只作用于 E2E 临时节点。
7. 在实体数据页验证 L2 实时、历史、质量、来源和技术证据。
8. 对临时节点指定一个现有规则并取消指定，只验证配置关系，不激活、不执行。
9. 退役临时节点并确认它从活动节点树消失。

## 测试结构

- Playwright 采用 Chromium、无头模式、单 worker 串行运行共享状态旅程。
- 单个场景超时 60 秒，整套全局超时 300 秒；不做自动重试，避免掩盖不稳定问题。
- 失败时保留截图、trace 和错误摘要；成功时不保留大体积 trace。
- 环境保护在测试启动前执行：必须显式设置 `ZIZU_E2E_ALLOW_LIVE_WRITES=1`，写入根节点名称必须严格等于 `E2E验证`，临时资源名称必须带本次运行 ID。
- 模拟遥测脚本使用后端已有 Paho MQTT 依赖，消息格式为 Neuron 标准 JSON：独立 `node_name`、`group`、毫秒时间戳和 `tags`。

## 失败语义

- 找不到按钮、数据未出现、质量不正确、历史为空、来源证据缺失、页面出现假成功提示，均直接失败。
- 外部前置条件不可用（站点、Neuron、MQTT、账号权限）时标记为阻断并给出明确原因，不把它算作通过。
- 清理失败必须进入报告，并输出遗留临时资源名称，便于人工定位。

## 日常与里程碑验收

- 普通节点管理改动：运行相关无头场景即可。
- Schema、数据帧、控制链或正式版本发布：运行完整无头主干；有失败时再用可见浏览器复现，正式里程碑保留一次可见浏览器抽查。
- 只有无头主干通过、必要的可见抽查通过且失败证据为空，才允许声称节点管理已交付。
