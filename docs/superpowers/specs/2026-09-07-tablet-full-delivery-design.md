# 自足IOT 正式界面完整交付规格与并行边界

日期：2026-09-07。状态：完整规格包已编写，待一次整体书面确认；产品实施、整合测试和发布尚未开始。

## 1. 本次交付什么

把已经认可的本机红金亮银 Demo，接入正式自足IOT的真实功能与数据。目标仍是实施工程师通过界面配置交付光储充 EMS，不新增一套平台。本次“全部”指运行首页、设备监控、节点点位实体、告警、调度、控制、系统工具的界面正式化，不代表所有工业场景、优化算法或现场工程配置已经完成。

唯一主干保持：真实节点树 → L0 原始点位 → L1 点位加工 → L2 全局实体 → 告警／调度策略／控制／光储充现场。L0/L1/L2不是树节点；同节点加工可读本节点L0，跨节点加工只读L2。采集、黑板、提交帧、质量、历史存储、JDM执行和统一控制的既有语义不重写。

已确认的首批A不变：先发布新外观与导航、真实运行首页和工程主干；告警/调度/控制/工具保留正式流程并统一样式。独立设备卡片与新编辑体验的规格现在一并确定，可独立开发，但不得让未完成模块进入首批路由或拖住已通过的首批发布。

## 3. 先统一的公共契约

- **外观与布局：** 自足IOT／光储充现场；基础红 `#bb0814`、暖金 `#b88a34`，亮银 `#fff → #f0f2f4 → #e0e4e8`，沿用最后确认的页头与品牌金。Noto Sans SC及既有中文回退，不下载新字体。正常绿色、故障红等语义色独立，不能全局把绿色替成品牌红。1280×800容纳十行表格；1024×768允许内容滚动；主要触控按钮至少44px；数据不足十条不补假记录。
- **入口与权限：** 只有一个正式应用和现有登录会话，运行与工程是导航分组，不是两套模式。保留既有角色矩阵和后端权限；操作员不能因为新页面获得模板、规则发布、启停、通知配置或系统工具权限。只读页加载、导航、关闭弹窗不得触发写操作。
- **实体身份：** 以 `entity_instance_id` 关联数据，校验 `node_id + definition_id`；显示节点、业务标识、单位。首页按已有L2和真实节点展示，不猜品牌名称、不以首台设备代替全站，不新增首页绑定配置层。站级总值必须已有明确站级L2，否则“未配置”。
- **实时与历史：** 复用 `api/committedFrameStream.ts` 的节点级快照与游标增量，以及现有投影/重取机制；同一可见节点去重订阅，离页释放，禁止每张卡单独轮询。节点A/B不宣称同一帧。时效使用既有实体门槛和观测语义，不建立第二套判定；无证据显示未知/无数据，旧值不装成当前值。历史按实体与单位分开、按需加载；非GOOD/缺口不连成正常曲线。
- **读写与恢复：** 配置继续经正式预览、摘要、配置修订、幂等及冲突校验。新建与编辑明确区分；未知结果不得伪报成功/失败或用新幂等键重做。已保存数据从服务端恢复；换对象不得沿用旧对象草稿或预览。分页选择只作用于可见当前页，改变范围清空选择。
- **调度与控制：** 完整JDM图是持久化事实。单表编辑只用于可无损往返的明确单表；多表或复杂图保持正式完整图编辑，不新增一种执行模式，不要求用户重新建策略。人工和JDM都经既有统一控制；受理、试算命中不等于设备成功，新L2回读才是成功证据。
- **最小接口调整：** 优先复用已存在的接口、类型和观测证据。工作台展示字段不足时由总协调在既有边界补齐，保持其他消费者兼容；不得各模块各造数据接口、状态存储或安全规则。无需新依赖、Schema迁移、规则引擎或采集通路。

## 4. 异步任务边界

书面规格整体确认后，先形成短实施计划并冻结公共契约提交，再同时启动三个模块任务；公共契约未就绪时只能做不依赖它的模块布局和专项测试，不自行猜接口。采用同一基线的独立工作树/分支，已完成模块即可交给总协调，不等所有任务一起结束。基线包含经筛查的已确认视觉参考，不能让任务依赖别处未跟踪且会继续变化的Demo文件；不把私有发布材料或临时文件整包纳入。

| 任务 | 独占范围 | 交付及依赖 |
|---|---|---|
| 总协调D0 | `App.tsx`、正式全局主题、`api/client.ts`、共享帧客户端/投影、构建与版本、必要的既有后端展示契约 | 统一导航/权限/数据契约；模块开始前提供基线；后续串行集成与发布 |
| R：运行与设备 | `pages/EMSWorkbenchPage.tsx`、新增`pages/DeviceMonitorPage.tsx`、专属`components/runtime-monitoring/`及专项测试 | R1真实首页先交；R2独立设备页后交；首页内现有控制区域也归R，其他任务不得同时修改 |
| E：工程主干 | `pages/NodeTreePage.tsx`、`components/NodeTagPanel.tsx`、`components/RawPointHistoryPanel.tsx`、`components/node/`与`components/data-trunk/`及专项测试 | 节点→导入→L0→加工→L2一次打通；共享帧投影除外，提交D0处理 |
| A：告警与策略 | `pages/AlarmCenterPage.tsx`、`pages/MinimalAlarmRulesPage.tsx`、`pages/DispatchStrategyPage.tsx`、`components/alarm-center/`、`components/dispatch-strategy/`、`components/AdminPanel.tsx`、`components/admin/`及专项测试 | A1原功能样式/回归先交；A2新告警表和原生JDM编辑后交；不重写控制链 |

R/E/A不交叉修改文件；共享组件先提出最小契约补丁，由D0串行处理。确需借用其他任务文件时先转移明确所有权，不让两个任务同时写。公共测试配置、锁文件、依赖、版本和发布文件只由D0管理；不新建微前端、共享事件总线或任务调度平台。

每个任务交回：源码提交、实际改动清单、验收条目与命令结果、未解决项、共享接口请求、是否具备合入条件。R1/R2、A1/A2分成独立可验收提交，首批只合入完整通过的R1/E/A1，不靠隐藏半成品或部分摘取业务代码发布。进度明确分“实现中／模块验收通过／已集成／已部署／现场复验通过”，不能把子任务完成称为产品已交付；状态以实际回报和验证为准。

## 5. 用最少重复换取可靠验收

1. 模块先跑受影响模型/接口/组件测试；失败留证据并定向修复，不反复运行无关全量测试。R/E/A使用独立测试数据与端口；不能共享可被另一任务删改的fixture或直接并行改同一现场数据库。若环境不支持隔离，仅串行执行有写副作用的集成测试，代码开发仍可并行。
2. 合入后由D0跑一次仓库要求的正式前后端完整门禁与构建。正式无头浏览器覆盖三角色、两种横屏、保存刷新恢复、错误/断流/质量、主干全流程及模块专项。主干包含隔离环境的真实配置保存，不只看页面能否打开。
3. 发布按A和后续两个明确检查点；每个固定制品都复用已记录源码/构建证据，只重跑因合并变化影响的专项及最终必要门禁。任何必需检查缺失为INCOMPLETE，失败为FAILED；Demo通过不能代替正式通过。现场真实设备写入、故障注入、真实HTTP测试发送不在此次UI验收授权内。
4. 1号机仅由D0操作：现状核对→当前配置备份及隔离恢复核验→固定ARM64制品替换应用→沿主干只读无头复验。保留host网络、`/dev/mqueue`、HTTP及DB/MQTT/Neuron；不清数据、不自动启用策略。有在途控制则停止切换并报告。失败回上一固定应用制品，不覆盖用户新配置、不做数据库回退。

完整验收必须覆盖全部模块规格中的条目，首批只标首批完成。截图/无头证据、源码版本、固定镜像摘要与实际现场复验分别记录，任何一个不能代替另外几个。
