# ZiZu 本机 Demo 正式产品化交付规格

日期：2026-09-08
状态：Accepted（维护者已逐项确认并整体确认）
目标版本：v1.0.5
正式基线：`origin/main` / v1.0.4（`2f36774`）

## 1. 目标

把维护者已经确认的本机平板 Demo 作为 ZiZu 正式产品的界面与操作标准，在不替换现有工业运行内核的前提下，完成一套面向 10.1 英寸横屏的正式应用：界面看起来、信息排布和操作路径与 Demo 一致，但所有值、状态、历史、来源、告警、策略和控制结果都来自正式 API、数据库和已提交数据帧。

完成后的唯一产品主线仍是：

```text
真实节点树 → L0 原始点位 → L1 点位加工 → L2 全局实体
                                           ↓
                         告警 / 调度策略 / 控制 / 固定 EMS 工作台
```

## 2. 两个不可混淆的真相

- **界面真相**：本机 Demo 决定页面结构、视觉层级、控件位置、表格密度、弹窗方式和主要操作流程。
- **运行真相**：正式 v1.0.4 后端决定认证、权限、committed L2、质量、时间、来源、配置修订、告警状态、JDM、控制安全门和回读结果。

正式实现不得复制 Demo 的合成数据、内存保存、场景切换、角色切换、故障注入、重置演示、模拟通知或模拟回读。页面缺少真实数据时显示“未配置”“无数据”“连接中断”或具体错误，不得用 0、正常状态或演示值填充。

## 3. 正式页面

### 3.1 运行首页

- 保留 Demo 的红金亮银外观、关键指标卡、固定光伏—储能—充电—电网/负荷拓扑、告警和调度摘要。
- 首页只读取已提交 L2。固定槽位为站点功率、光伏功率、储能功率、储能 SOC、充电功率。
- 自动绑定只允许命中显式列出的标准 `definition_key`；零个候选显示未配置，多个候选显示需人工选择，不得按名称或地址猜测。
- 实施工程师可以在弹窗中为固定槽位指定一个真实 L2；保存受配置修订、权限和幂等约束。人工绑定优先于自动绑定，解除后恢复确定性自动匹配。
- 功率槽只接受数值 `kW`，SOC 只接受数值 `%`；单位不符回到 L1 修正，首页不换算。
- 没有可信方向依据时保留拓扑但不画流向；不能以前端求和制造站点总功率。

### 3.2 设备监控

- 使用 Demo 的筛选区、统计摘要、每页六张亮银拟物设备卡和同页详情弹窗。
- 卡片、搜索、分页、告警计数、实时值、质量和时间全部使用真实节点与 committed L2。
- 主/副指标只按明确设备类别和标准实体定义排序；不能按显示名称模糊猜测。无法分类的节点进入“其他”。
- 设备详情默认每页 10 个实体，可切换 20 个；历史和来源均围绕当前选择的同一 L2。
- `GOOD` 才显示当前值；其他质量保留带时间的最后证据并明确标为非当前。接口失败不得呈现成零或正常。

### 3.3 节点与数据

- 使用 Demo 的节点树、密集表格与按需弹窗，但保留正式节点 CRUD、Neuron 导入、配置并发和未知结果恢复。
- L0 显示协议原值、实时/历史、质量、数据时间、接收时间和 Neuron→MQTT→数据接收→数据帧→L0 链路诊断。
- 从 L0 选择点位后打开点位加工弹窗；支持直接使用、比例/偏移、0/1 布尔映射、枚举/状态、强类型公式和多点组合。
- 同节点输入可以读本节点 L0；跨节点计算只能选择其他节点的 L2。检查成功后才可生成计划并发布，发布结果形成稳定 L2。
- L2 页面显示实时/历史、质量、时间、来源证据和当前加工修订；高级证据放入抽屉或弹窗，不挤占主表。
- 点位加工模板是可选复用资产，不是首台设备接入的前置步骤。

### 3.4 告警中心

- 当前告警、历史告警和通知记录使用正式表格，默认每页 10 条，可切换 20 条。
- 事件详情、确认、归档、规则编辑、HTTP 通知绑定与投递详情使用弹窗或抽屉。
- 操作员可查看和确认有权限的真实事件；规则配置和 HTTP 配置继续受工程/管理员权限约束。
- 不提供“模拟故障发生/恢复”。告警状态只由 committed L2 和正式告警状态机产生。

### 3.5 调度策略

- 产品概念只叫“调度策略”，JDM 是其内部唯一执行语义。
- 正式编辑路径保持三步：选择多个 L2 输入 → 编辑一张原生 JDM 决策表 → 绑定一个或多个可控 L2 输出。
- 时段、SOC 和 2充2放只是可以删除的表格示例，不形成第二套策略模式。
- 草稿、试算、发布、启用、停用、失败锁、事件和控制回读全部沿用正式 API；试算不写设备。
- 无法无损表示为单张表的既有 JDM 继续使用完整图编辑，不得自动改写或丢失未知字段。

### 3.6 手动控制

- 使用 Demo 的目标输入、门禁说明、二次确认和回读状态布局。
- 可控对象只能来自后端正式控制目录。确认、命令、幂等、防重复、限值、质量、新鲜度和权限均由后端复核。
- “接口受理”只显示为等待回读；仅后端返回的新 committed L2 回读可以把命令变为成功。
- 本机验收使用隔离协议边界；1号机首轮只读。任何真实设备写入必须另获当次明确授权。

### 3.7 系统工具

- 按 Demo 视觉分组 NanoMQ/MQTT、HTTP 通知、故障映射、数据与系统状态。
- 复用现有正式 CRUD、测试和权限；高风险 SQL/清理功能不因视觉改版降低确认与审计要求。

## 4. 应用外壳与权限

- 品牌为“自足IOT”，运行标题为“光储充现场”，副标题为“简单配置，交付光储充 EMS”。
- 使用已确认的深红、暖金、亮银和现有 Noto Sans SC 中文字体栈，不增加字体或 UI 依赖。
- 运行底部主导航为运行首页、设备监控、手动控制；运行首页保留告警入口。
- 工程配置入口仅对管理员和实施工程师显示；工程区包括节点与数据、告警配置、调度策略、系统工具。
- 不建立运行/工程两套应用或两套账户；服务端权限永远是最终边界。
- Demo 专属横幅、角色下拉、场景下拉和重置按钮不得出现在正式构建。

## 5. 通用交互状态

每个页面和每个可写操作都必须有明确的：加载中、真实空态、断线、超时、无权限、配置冲突、请求结果未知、成功收据。所有按钮必须连接正式动作；没有正式动作的控件删除或明确禁用，不能留下“看起来能点”的装饰按钮。

表格默认每页 10 条并提供 20 条选项；真实记录不足 10 条时只显示真实记录，不补演示行。主要触控按钮高度不低于 44px，键盘焦点可见，弹窗可关闭且不会因异步刷新抢走用户输入。

## 6. 实现边界

- 沿用 React 18、TypeScript、Vite、Tailwind、现有 CSS、FastAPI、PostgreSQL/TimescaleDB、NanoMQ、Neuron 和 GoRules JDM。
- 不增加 Redis、Kafka、新微服务、第二规则引擎、自由页面设计器、任意脚本或新前端框架。
- 正式页面继续位于 `frontend/src`；`frontend/demo-tablet` 不进入正式 Vite 依赖图。
- 优先重排现有正式组件并复用 Demo 局部样式；不重写数据内核，不复制整套平行前端。
- 除首页固定槽位的持久化人工绑定外，当前审计没有发现必须新增的后端功能。

## 7. 验收

- 视觉与交互：在 1280×800 和 1024×768 两种横屏尺寸逐页截图并跑交互清单。
- 数据真实性：正式页面只请求正式 API；构建产物中不得出现 Demo 场景、固定设备值、模拟回读和内存发布逻辑。
- 功能：每个可见按钮至少覆盖成功、禁止/无权限或失败中的实际状态；节点/L0/L1/L2/告警/策略/控制/工具均有对应正式请求证据。
- 安全：本机完整体验只使用隔离数据和隔离协议适配器；部署到1号机后先做只读主干，未经另行授权不下发真实控制、不发送测试通知、不发布现场加工。
- 发布：全部本机门禁和集成验收通过后才升版 v1.0.5；一次构建固定 ARM64 摘要，一次替换 ZiZu 容器，TimescaleDB、NanoMQ 与 Neuron 不重启。
