# ZiZu 解决方案交付硬切与最小数据主干设计

**状态：** 已确认

**日期：** 2026-08-25

**产品主线：** `节点 → L0 原始点位 → L1 点位加工 → L2 全局实体 → 告警 / JDM / 控制 / 固定 EMS 工作台`

## 1. 决策

ZiZu 不再把“解决方案”作为产品层级、配置容器或交付入口。删除解决方案包、解决方案安装、统一交付验收和设备实例中间层；所有现场配置回到真实节点树，并通过 L0、L1、L2 三层数据主干直接完成。

保留工业系统不可省略的安全属性：强类型、原子发布、稳定身份、质量与时间戳、来源证据、配置修订号、权限、审计、幂等和失败回滚。它们是主干内部能力，不再包装成新的产品模块。

## 2. 最小产品模型

```text
节点树
 └─ 节点
     ├─ L0 原始点位
     │    ├─ 实时值
     │    └─ 历史值
     ├─ L1 点位加工
     │    ├─ 单文件点位加工模板
     │    ├─ 当前安装修订
     │    ├─ 输入绑定与强类型规则
     │    └─ 预览、发布和就地验证
     └─ L2 全局实体
          ├─ 稳定业务身份
          ├─ 实时值与历史值
          ├─ 类型、单位、质量与时间戳
          └─ 来源证据
               ↓
          告警 / JDM / 控制 / 固定 EMS 工作台
```

### 2.1 节点

节点是站点、系统、设备或逻辑对象在物理树中的唯一归属对象。节点直接承载 L0、已安装的 L1 和 L2，不再另外创建“设备实例”。站点、光伏、储能、充电、负荷、PCS、BMS、电表等差异由节点类型表达。

### 2.2 L0 原始点位

L0 是协议采集事实，保留品牌字段、工程值、质量、观测时间和接收时间。L0 只用于诊断和 L1 输入；告警、JDM、控制和工作台不得直接引用 L0。

### 2.3 L1 点位加工

L1 是挂载在输出所属节点上的版本化配置。它负责品牌字段映射、单位换算、枚举和状态解析、多点组合、故障多码映射、质量与时间处理，以及已确认的强类型跨节点公式。跨节点计算只能读取其他节点的 L2，不得读取其品牌 L0。

L1 不保存普通中间时序值。其持久事实只有模板、不可变修订、输入输出定义、确定绑定、当前安装和发布审计。

### 2.4 L2 全局实体

L2 是上层应用唯一稳定的数据接口。每个 L2 实体直接属于一个节点，由稳定 UUID 和业务语义键标识；更换品牌、点位地址或 L1 修订不得改变实体 UUID。L2 同时提供实时快照、历史事实和完整来源证据。

“全局”表示在站点内被所有上层模块统一引用，不表示跨站、多租户或全局变量。

## 3. 唯一配置流程

实施工程师只执行一条主流程：

```text
选择节点
 → 选择或导入点位加工模板
 → 自动匹配 L0 / 选择跨节点 L2
 → 处理缺失或歧义
 → 预览 L0 → L1 → L2 结果
 → 原子发布
 → 查看 L0 与 L2 实时值完成就地验证
```

预览不改变运行配置。存在缺失、歧义、类型不符、单位不兼容、循环依赖或质量策略错误时，发布按钮禁用。发布时重新核对模板摘要、输入集合、依赖图和基础配置修订号；任何条件变化都拒绝整次发布，不产生半成品。

## 4. 点位加工模板

点位加工模板使用一个规范 JSON 文件，例如 `pcs-en9.zizu-point-processing.json`。文件只包含：

- 模板键、显示名称、设备类别、品牌型号和不可变修订；
- 强类型输入选择器；
- L2 输出语义、类型、单位、方向和新鲜度；
- 允许的加工规则、质量策略和时间策略；
- 内容摘要所需的规范字段。

模板不得包含现场凭据、节点 UUID、客户拓扑、安装计划、验收清单、页面资产或任意 Python/JavaScript。导入只登记不可变模板修订，不改变现场运行配置，也不增加配置修订号；把模板发布到某个节点时才产生一次运行配置修订。

不再提供 ZIP、解决方案清单、多资产包、参数契约、覆盖层或包升级机制。模板复用的最小单位就是这个文件。

独立“设备模板”不再作为产品概念或菜单存在；协议驱动的必要连接配置留在协议接入处，品牌语义适配统一进入点位加工模板。

## 5. 最小数据结构

### 5.1 配置关系

| 对象 | 最小职责 |
|---|---|
| 节点 | 树结构、节点类型、显示名称和稳定身份 |
| L0 点位目录 | 节点、协议来源键、类型、单位和采集元数据 |
| 点位加工模板 / 修订 | 可复用定义及其不可变内容摘要 |
| 点位加工输入 / 输出 / 规则 | 强类型加工图 |
| 已安装点位加工 | 节点当前生效的模板修订 |
| 输入绑定 | L1 输入到本节点 L0 或跨节点 L2 的确定关系 |
| L2 实体 | `node_id + definition_key` 的稳定业务实例 |
| 配置修订 | 每次运行配置原子发布产生的内部递增修订号 |
| 配置审计 | 操作者、动作、资源、前后摘要、结果和时间 |

L2 实体表直接保存 `node_id`，删除 `device_instance_id` 依赖。实体定义可以作为复用语义目录保留，但实体实例不再通过设备实例或解决方案槽位生成。

### 5.2 实时与历史

全平台只保留两类历史事实和两类最新快照：

| 层级 | 历史 | 实时 |
|---|---|---|
| L0 | 共享 L0 时序超级表 | 共享 L0 latest 表 |
| L1 | 不保存普通中间时序 | 当前生效配置与运行状态 |
| L2 | 共享 L2 时序超级表 | 共享 L2 latest 表 |

L2 历史必须保存实体 UUID、强类型值、质量及原因、观测/接收/计算时间、L1 修订和来源事件引用。不同节点、设备类型、品牌和业务语义通过普通列和索引区分，不为节点、设备或层级新建超级表。

### 5.3 配置修订号

“站点配置版本”收缩为内部“配置修订号”，不设菜单、页面或通用管理 API。最小实现只有：

- 一个保存当前修订号的单例状态；
- 一张追加式修订记录表；
- 一张追加式配置审计表。

L1、告警、JDM、控制配置的每次成功发布，都在同一数据库事务内锁定当前修订、复核基础修订、写入业务配置、递增修订并写审计。失败时全部回滚。模板导入、实时数据写入、告警状态变化和控制执行不增加配置修订号。

## 6. 数据流

```text
Neuron / MQTT / Modbus / OPC UA
 → L0 历史与 latest 同事务写入
 → 当前 L1 修订执行强类型加工
 → L2 历史、latest、来源证据与 outbox 同事务写入
 → 事务提交
 → 认证实时通道推送
 → 告警 / JDM / 控制 / 固定 EMS 工作台消费 L2
```

数据库事务未提交时不得推送。乱序观测可以进入历史，但不得倒退 latest。BAD、STALE、缺失输入和计算错误必须形成明确质量，不得伪装为有效值或零值。L2 来源证据必须能追溯到参与计算的 L0/L2 事件和生效的 L1 修订。

## 7. 界面

### 7.1 导航

保留以下主入口：

- `EMS 工作台`
- `节点与数据`
- `告警中心`
- `告警配置`
- `JDM`
- `控制`
- `系统工具`

删除“解决方案交付”和独立“设备模板”。“实体管理”不再是与节点树平行的主入口；L2 定义和实例在节点的 L2 页签中管理和查看。

### 7.2 节点与数据

左侧始终是物理节点树；右侧固定为三个页签：

- `L0 原始点位`：实时值、质量、时间戳、来源、搜索和历史趋势；
- `L1 点位加工`：模板选择/导入/导出、输入匹配、公式与映射、阻断、预览、发布和当前修订；
- `L2 全局实体`：实时值、质量、时间戳、历史趋势、来源证据和上层消费者。

顶部固定显示 `采集 → L0 → L1 → L2 → 上层应用`，并用状态指示当前节点的数据链是否完整。

### 7.3 固定 EMS 工作台

EMS 工作台根据节点类型和 L2 标准语义组织光伏、储能、充电、负荷、能流、SOC、功率、设备可用性、活动告警和数据质量。不提供页面设计器，不通过解决方案包安装页面。

## 8. 模块内验证

不建设验收中心、通用验收报告模型或验收清单执行器。验证回到产生事实的模块：

- L1：展示最近 L0 输入、L2 输出、质量、时间戳、来源证据和修订；
- 告警：展示规则匹配、触发、确认和现场恢复状态；
- JDM：提供对固定输入快照的试运行结果；
- 控制：展示权限、限值、联锁、命令状态和回读；
- 工作台：展示消费的 L2 实体及质量。

这些验证读取正常运行事实，不生成第二套“验收事实”。操作审计、告警事件、JDM 执行和控制命令仍按各自安全要求持久化；删除专为验收聚合而存在的报告和幂等表。

## 9. 公开接口边界

主线只需要直接资源接口：

- 查询节点数据主干；
- 查询、导入和导出单文件点位加工模板；
- 为节点预览点位加工计划；
- 原子发布节点点位加工；
- 查询节点 L0/L2 实时、历史和来源证据；
- 由告警、JDM、控制各自提供配置、运行和审计接口。

删除所有 `solution-packages`、`install-plans`、`solution-installations`、`delivery-reports` 和解决方案验收接口。不保留旧路由、别名、兼容代理或双写。

## 10. 硬切迁移

采用一次发布硬切，不长期维护新旧两套语义。迁移顺序固定为：

1. 对数据库做完整备份，并在隔离环境验证可恢复；
2. 建立通用配置修订/审计结构和直接节点归属；
3. 把点位加工模板及修订从解决方案资产中剥离为独立模板；
4. 把 L2 实体从设备实例归属迁移为节点直接归属；
5. 把当前已安装 L1、输入输出绑定和上层引用接到新结构；
6. 把仍有审计价值的旧配置变更摘要转换为通用配置审计；
7. 删除解决方案、设备实例和验收专用结构；
8. 启动新版本并执行只读主干验证。

必须保留：

- 节点 UUID 和树结构；
- L0 点位身份、历史、latest 和去重事实；
- 点位加工模板内容、当前安装和绑定；
- L2 实体 UUID、历史、latest、来源证据和上层引用；
- 告警规则与事件、JDM 规则与执行事实、控制命令与审计；
- 用户、角色和系统配置。

可以删除：

- 解决方案包内容、资产、安装计划、安装记录和包级幂等；
- 统一交付报告和各模块验收报告；
- 设备实例、实例槽位、解决方案绑定候选等中间身份；
- 解决方案页面、路由、权限、API 客户端和参考包构建逻辑；
- 只为上述概念存在的测试、文档和发布元数据。

若任一 L2 实体无法唯一映射到节点、任一上层引用将丢失、或模板内容无法独立还原，迁移必须在删除前整体失败。回滚只能恢复完整数据库备份并启动旧固定摘要容器，不做跨 Schema 反向兼容。

## 11. 现有功能的收敛

- 既有告警配置保留，但发布改用通用配置修订；删除告警验收报告层。
- JDM 保留为唯一上层规则执行语义，不再增加平行通用规则引擎。
- L1 保留专用强类型加工规则，以支持跨节点计算和复杂公式；不允许任意脚本。
- 既有独立业务指标模板不形成新的产品层级。所需窗口/统计能力以后作为明确的 L1 规则类型输出 L2；本次硬切不继续扩张独立业务指标交付体系。
- 控制和工作台继续只引用 L2；控制安全链不因删除解决方案而放宽。

## 12. 明确不做

- 不做解决方案、项目空间、多租户或站点复制；
- 不做通用页面设计器、工作流引擎或万能表达式引擎；
- 不做设备模板与点位加工模板并存；
- 不做模板商城、模板依赖、模板包或覆盖层；
- 不做统一验收中心和报告框架；
- 不为 L1 中间值、节点或设备单独建超级表；
- 不保留已删除概念的兼容 API、兼容表或长期迁移开关。

## 13. 完成判据

硬切完成必须同时满足：

1. 产品导航、公开 API、生产服务和数据库均不存在“解决方案交付”运行入口；
2. 在界面中可以查看任一节点的 L0 实时/历史和 L2 实时/历史/来源；
3. 通过单文件模板完成“预览 → 原子发布 → 实时验证”，无需修改源码、SQL 或模板正文；
4. 品牌模板切换后 L2 UUID 和告警/JDM/控制/工作台引用保持不变；
5. 发布冲突或任一阻断导致零运行配置写入；
6. 迁移前后的节点、L0、L2、告警、JDM 和控制事实数量及关键摘要对账通过；
7. 所有被删除接口返回不存在，前端无死链，数据库无遗留解决方案外键；
8. 完整后端测试、前端构建、数据库迁移/回放、进程重启和认证实时推送验证通过；
9. 现场验证只读进行，不执行自动策略或设备写入。

## 14. 被取代的设计

本设计取代 ADR-0006 的 `SolutionDelivery` 产品接口，以及产品目的地、参考包和后续规格中依赖解决方案包、设备实例槽位、统一交付报告的部分。L0/L1/L2 数据一致性、告警状态机、JDM、控制安全、认证和部署安全设计继续有效。
