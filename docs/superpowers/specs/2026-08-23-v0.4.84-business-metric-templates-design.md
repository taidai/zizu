# v0.4.84 业务指标模板与统计实体设计

**状态：** 已确认

**日期：** 2026-08-23

**基线：** PR #48 / `ea8b01e` / Schema 042

## 1. 目标

v0.4.84 在既有“物理节点树 + L0 原始点位 + L1 点位加工 + L2 全局实体”数据主干上，交付可配置、可修正、可审计的 EMS 业务统计能力。实施工程师从业务指标目录选择指标和目标节点，确认平台解析出的语义来源并填写最少参数，即可生成 L2 统计实体；不编辑 SQL、UUID、通用表达式、JSON/YAML，也不为指标创建独立超级表。

首个交付范围是八项光储充 EMS 指标：

1. 今日光伏发电量；
2. 今日储能充电量；
3. 今日储能放电量；
4. 今日电网购电量；
5. 今日电网上网量；
6. 今日充电桩电量；
7. 15 分钟平均功率；
8. 今日负荷峰值。

本版本不提供通用可视化指标设计器，不允许实施人员编写任意窗口公式，不启用统计实体自动控制，不改动现场设备，也不部署 1 号机。发布与部署在功能、机器验收和独立复审完成后另行确认。

## 2. 产品位置

统计实体仍是 L2 全局实体，不增加 L3：

```text
物理节点树
  ├─ L0 原始点位
  ├─ L1 点位加工
  │    ├─ 设备语义标准化
  │    └─ 跨节点即时公式
  └─ L2 全局实体
       ├─ 实时实体：即时值、质量、时间戳、来源
       └─ 统计实体：当前窗口投影 + 不可变历史修订
              ↓
       画面、报表、告警、策略仿真
       （自动控制依赖链强制拒绝）
```

业务指标模板是解决方案包中的高层配置资产。安装时，它解析目标节点和语义来源，冻结站点时区、来源清单、计算方法和质量门槛，并生成内部 L1 点位加工修订及稳定 L2 实体实例。该内部编译结果不作为新的产品层级展示。

## 3. 领域不变量

1. 业务指标模板不可变且版本化；升级必须生成预览和新修订。
2. 一个统计实体保持稳定实体 ID；语义不变的模板升级只增加修订，语义破坏性变化必须创建新实体。
3. 站点创建时必须配置 IANA 时区；数据库统一存 UTC，窗口按安装修订冻结的站点时区对齐。
4. 当前窗口暂定值只存在于可恢复运行投影；`t_l2_observations` 只接收完成或修正事实。
5. 同一实体、窗口和结果修订不可覆盖；旧修订始终可查询。
6. 来源在安装时确定并冻结；运行异常只降低质量，不自动切换来源。
7. 能量指标优先使用权威累计量；只有累计量语义来源不存在时，才允许冻结功率积分回退并标记 `estimated`。
8. 缺测不得按零填充；覆盖不足产生 `UNCERTAIN` 或 `BAD`，不能伪造正常结果。
9. 统计实体和其任意上游依赖一旦带窗口时间语义，自动策略与控制编译必须拒绝整条依赖链。
10. 停用只停止新计算，保留实体、历史和修订；重新启用生成新安装修订，业务对象不硬删除。

## 4. 深模块与 seam

### 4.1 `BusinessMetricDelivery`

面向公开 REST 和解决方案安装，只暴露配置交付行为：

```python
class BusinessMetricDelivery:
    def catalog(self, *, node_id: UUID) -> tuple[MetricTemplateSummary, ...]: ...
    def preview(self, request: PreviewMetricInstallation) -> MetricInstallationPlan: ...
    def apply(self, command: ApplyMetricInstallation) -> MetricInstallation: ...
    def inspect(self, *, node_id: UUID) -> tuple[MetricInstallationState, ...]: ...
    def change_state(self, command: ChangeMetricState) -> MetricInstallation: ...
```

模块内部隐藏模板解析、语义来源解析、累计量/积分方法选择、内部点位加工编译、实体身份、能力契约、计划摘要、幂等、站点版本和审计。`preview` 零运行写入；`apply` 在 PostgreSQL 单事务中复核计划并原子安装。

### 4.2 `MetricProjection`

运行模块只有三个入口：

```python
class MetricProjection:
    def observe_committed(self, event_ids: tuple[UUID, ...]) -> ProjectionReceipt: ...
    def advance(self, *, now: datetime) -> ProjectionReceipt: ...
    def recompute(self, command: RecomputeMetric) -> RecomputeReceipt: ...
```

它隐藏窗口边界、水位线、累计量分段、积分、覆盖率、重启重放、迟到数据、封窗、修正和历史写入。它只消费已经提交的 L2 事件身份和审计重算命令，不旁路 `DataTrunk` 读取未提交数据。

### 4.3 `EntityCapabilityGuard`

告警、策略、控制和仿真编译器通过一个检查 seam 读取完整依赖闭包：

```python
class EntityCapabilityGuard:
    def check(self, *, consumer: ConsumerKind, entity_ids: tuple[UUID, ...]) -> CapabilityDecision: ...
```

依赖闭包由当前 `t_point_processing_dependencies` 与业务指标冻结来源联合递归得到。自动控制遇到 `temporal_semantics=windowed`、`control_eligible=false`、默认值或不确定质量能力时稳定拒绝，不依赖前端隐藏按钮。

## 5. 模板与安装模型

解决方案包新增 `business_metric_template` 资产，Schema 为 `zizu.business-metric/v1alpha1`。模板声明：

- 稳定模板 ID、修订、显示名和适用目标节点类型；
- 输出实体定义、数据类型、单位和时间语义；
- `aligned_daily`、`rolling` 等强类型窗口；
- 语义来源候选、累计量优先级和功率积分回退；
- 能量流方向 `positive|negative|both` 及是否把选中方向归一为正值；
- 聚合器 `counter_delta`、`power_integral`、`average` 或 `maximum`；
- 覆盖率、允许迟到、自动修正范围和保留策略；
- `controlEligible: false` 固定能力。

示例：

```yaml
schemaVersion: zizu.business-metric/v1alpha1
id: ems.pv-energy-today
revision: 1
displayName: 今日光伏发电量
targetNodeType: SITE
output:
  entityDefinition: site.pv_energy_today
  dataType: FLOAT
  unit: kWh
  temporalSemantics: windowed
window:
  kind: aligned_daily
sources:
  - method: counter_delta
    entityDefinition: pv.energy_total
    priority: 1
  - method: power_integral
    entityDefinition: pv.active_power
    priority: 2
quality:
  minimumCoverage: 0.98
correction:
  automaticHorizon: 7d
capabilities:
  controlEligible: false
```

安装预览使用节点子树、节点类型和实体定义解析来源。`counter_delta` 有唯一完整候选时选中；不存在时才考虑 `power_integral`；任一层级出现歧义或必需来源缺失都形成 blocker。计划显示实际来源实体、方法、估算标记、窗口、时区、覆盖率和预计输出实体，应用后全部冻结。

## 6. Schema 043

Schema 043 只扩展 Schema 042，不改写既有迁移：

| 表 | 责任 |
|---|---|
| `t_business_metric_templates` | 模板稳定身份 |
| `t_business_metric_revisions` | 不可变模板内容、规范摘要和包来源 |
| `t_business_metric_installation_plans` | 基准站点版本、来源摘要、时区和计划摘要 |
| `t_business_metric_plan_items` | 来源、输出、能力和 blocker 的唯一计划明细 |
| `t_installed_business_metrics` | 目标节点、稳定实体、模板修订、内部点位加工安装、冻结时区和状态 |
| `t_business_metric_source_bindings` | 冻结来源实体、顺序、方法和估算标记 |
| `t_business_metric_projections` | 每个安装当前窗口的可覆盖运行投影、水位线、覆盖率和恢复状态 |
| `t_business_metric_window_results` | 窗口结果修订、生命周期、来源摘要、计算方法、覆盖率及可选 L2 事实引用 |
| `t_business_metric_recomputations` | 人工/自动重算范围、操作者、审批、状态和证据 |
| `t_entity_capability_contracts` | 实体能力契约不可变修订及生效安装 |
| `t_business_metric_audit` | 安装、升级、停用、启用、重算和拒绝证据 |

`t_l2_observations` 和 `t_l2_latest` 仍是唯一正式 L2 历史与已完成最新事实结构，不为指标或节点新建超级表。业务指标安装会生成内部 `t_point_processing_revisions` 记录，因此既有 `processing_revision_id` 来源约束继续有效。

`t_business_metric_projections` 允许原子更新，不安装 append-only trigger；它是可从 L2 历史和检查点重建的运行状态。其余修订、结果和审计表不可变。`t_business_metric_window_results` 的 `completed/corrected` 行必须引用一个 `t_l2_observations(event_id, observed_at)`；`invalid` 行不得引用 L2 事实。

TimescaleDB 对统一 L2 历史采用压缩和保留策略。完成结果、修订关系和审计长期保留；原始高频明细保留期由站点配置，但结果必须保留来源实体清单、时间范围、事件计数、首尾事件身份和内容摘要，保证可验证性。

## 7. 时间、窗口与水位线

所有存储时间为 UTC。日窗口按冻结 IANA 时区计算本地 `[00:00, 次日00:00)`，必须正确处理 23/24/25 小时日。滚动 15 分钟平均功率按每分钟对齐的窗口结束时间发布，窗口为 `(end-15m, end]`。

事件时间优先使用来源中可信采集时间；缺失或不可信时回退数据库接收时间，并在来源证据中记录 `timeBasis=received_at`。水位线只从已提交来源事件推进。窗口结束且水位线超过 `window_end + allowed_lateness` 后产生首个 `completed` 事实；自动修正范围内到达的迟到事件产生新的 `corrected` 修订，不覆盖旧事实。

自动修正范围固定为：滚动窗口 6 小时、日窗口 7 天、月窗口 35 天。超出范围必须提交审计重算命令并由管理员批准。重启后从投影检查点和最后已提交事件身份继续，重复事件、重复 tick 和重复重算命令都必须幂等。

## 8. 计算和质量

### 8.1 累计量

累计量模板同时冻结计数器位宽、最大值、复位规则和翻转规则。窗口增量按连续分段求和：正常递增取差值；明确翻转按位宽补偿；明确复位从复位后的值重新累计；无法区分复位、翻转或异常倒退时结果为 `BAD`，绝不产生负电量。

### 8.2 功率积分

功率积分只作为安装时冻结的回退方法，使用相邻样本梯形积分。超过模板最大采样间隔的空洞不补零；覆盖率按实际可积分时长除以窗口时长计算，结果标记 `estimated=true`。

充/放电、购/上网等双向能量必须由模板冻结功率符号约定：只积分选定方向，反方向片段按零贡献而不是缺测，选中负方向时先取绝对值再积分，最终电量永不为负。来源定义的方向约定与模板不一致时安装被阻断。

### 8.3 平均与峰值

15 分钟平均功率按时间加权平均，不按样本数平均。今日负荷峰值取质量合格样本最大值，并保留峰值发生时间和来源事件身份。

### 8.4 生命周期与质量

结果生命周期为 `provisional | completed | corrected | invalid`；L2 数据质量继续使用现有 `GOOD(192) | UNCERTAIN(64) | BAD(0)`，不得混成一套枚举：

- 当前窗口始终为 `provisional`，可同时为 GOOD 或 UNCERTAIN；
- 覆盖率达到模板门槛且来源有效，完成事实为 GOOD；
- 覆盖率低于正常门槛但不低于模板最低可用门槛，完成事实为 UNCERTAIN；
- 来源 BAD、计数器歧义或低于最低可用门槛，窗口为 `invalid`，只写窗口结果台账，不写 L2 历史事实；
- 修正事实沿用计算后的 GOOD/UNCERTAIN 质量，并以 `corrected` 生命周期区分。

## 9. 实时与历史读取

既有 L2 读取 interface 保持稳定。读取实时统计实体时，查询层优先返回 `t_business_metric_projections` 的当前窗口暂定值，并携带 `provisional`、窗口范围、覆盖率、估算标记、质量和更新时间；若无活动投影，则返回最后完成事实。即时实体继续读取 `t_l2_latest`。

历史查询从 `t_l2_observations` 返回正式事实，并联接 `t_business_metric_window_results` 返回窗口和修订信息。默认每个窗口返回最新修订，`include_revisions=true` 时返回全部完成/修正版本；无有效事实的窗口以结果台账中的 `invalid` 缺口呈现，不伪造零值。

## 10. 界面

节点树仍只显示真实物理/逻辑节点。选择节点后：

- L2 页签分为“实时实体”和“统计实体”；
- “统计实体”顶部提供业务指标目录，显示适用指标、来源方法、目标实体、窗口、质量门槛和安装状态；
- 选择指标后显示来源预览，明确累计量优先或功率积分估算、冻结来源、站点时区和 blocker；
- 安装后卡片显示当前值、`暂定/已完成/已修正/无效`、质量、覆盖率、窗口范围和更新时间；
- 历史抽屉显示趋势、窗口修订链、来源证据、计算方法和人工重算审计；
- engineer 可在允许范围内预览/执行重算，超出自动范围显示管理员审批；
- 停用保留历史并停止新计算，重新启用明确生成新修订；
- operator 只读，界面不提供通用指标编排、SQL 或任意表达式入口。

## 12. 控制安全

统计实体可用于画面、报表、历史、告警和策略仿真。自动策略激活和控制命令编译必须在运行前调用 `EntityCapabilityGuard`，递归遍历目标及所有来源；任何窗口实体、`control_eligible=false`、默认值依赖或能力契约缺失都返回稳定拒绝码并写审计。控制运行时再次执行同一检查，防止旧计划或旁路调用绕过编译门禁。

## 13. 机器验收

不可变验收报告必须使用真实 PostgreSQL 和公开接口证明：

1. 八项模板可从目录预览并以最少参数安装；
2. 来源解析、累计量优先、积分回退和冻结成员符合计划；
3. 在线连续计算、进程重启、离线补算和人工重算对相同事件集合产生相同结果摘要；
4. 当前窗口只更新运行投影，不制造 L2 历史修订；
5. 完成和修正事实写入统一 L2 超级表，旧修订可查询；
6. 迟到数据在范围内生成修正，范围外要求审计审批；
7. 断点、缺测、复位、翻转和歧义均按契约降级，不补零、不产生负电量；
8. IANA 时区和夏令时边界正确；
9. 停用/启用、升级和来源变更保留稳定实体身份与历史；
10. 自动策略与控制对统计实体及其依赖链稳定拒绝；
11. API 权限、幂等、计划过期、事务回滚和审计通过；
12. 前端生产构建、完整后端测试和 Schema 043 fresh/042-upgrade/replay 通过。

性能门槛：参考站 500 个即时 L2 来源、100 个统计实体时，1 秒 runtime tick 的数据库事务 p95 小于 500 ms；日窗口人工重算 30 天在 60 秒内完成；重复重放不增加事实或修订数量。性能测试使用固定数据集并在报告中记录环境，达不到门槛不得形成 RC。

## 14. 发布边界

本规格目标版本为 `v0.4.84-rc.1`、Schema 043。PR #48 保持冻结；实现分支从 `ea8b01e` 叠加。完成全部门禁和独立复审后才创建不可变 RC 标签与固定镜像摘要。1 号机部署不是本实施计划的一部分，后续必须再次确认维护窗口，并继续保留 `network_mode: host`、`/dev/mqueue`、无 Caddy/TLS、无自动策略验证和无设备写入的现场约束。
