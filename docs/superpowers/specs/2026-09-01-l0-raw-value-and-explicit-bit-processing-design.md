# L0 原值保真与 BIT 显式加工设计

**状态：** 已确认（Accepted）

**日期：** 2026-09-01

**权威依据：** `2026-08-27-zizu-platform-core-architecture-design.md`、ADR-0011

**适用范围：** Neuron/MQTT 进入 L0、L0 实时与历史、L1 直接使用与 `0/1` 转布尔、L2 质量传播

## 1. 目的

修正当前 `BIT → BOOL` 在 L0 入口发生隐式转换的问题，使平台重新严格服从：

```text
真实节点树 → L0 原始点位 → L1 点位加工 → L2 全局实体 → 上层应用
```

设备上传数字 `0` 时，L0 实时、历史、来源证据和传输接口都必须仍是数字 `0`；只有实施工程师明确配置
L1 的 `0/1` 转布尔加工后，L2 才能出现布尔值 `false`。本设计不是把前端的 `false` 格式化成 `0`，
而是硬切 L0 数据契约，消除采集入口的隐藏业务转换。

## 2. 当前问题与根因

Neuron 点位目录当前把协议类型 `BIT` 登记为工程值类型 `BOOL`。L0 接收器随后按该类型把数字 `0/1`
转换为 `false/true`，数据库 `raw_value_bool`、实时快照、WebSocket 和页面因此只能得到布尔值。

这能避免 BOOL 运行计算发生类型冲突，却混淆了两个不同事实：

- L0 应回答“设备实际传来了什么”；
- L2 应回答“这个值在业务上表示什么”。

只修改页面显示会让页面、数据库、来源摘要和 L1 输入继续相互矛盾；在 L0 同时永久保存“原值＋规范值”
又会增加概念、存储和查询负担。因此采用单一真实边界：L0 只保存原值，所有业务类型转换显式进入 L1。

## 3. 已确认决策

### 3.1 L0 原值契约

- L0 只保存设备实际上传的标量值，不保存规范值或业务解释值。
- 数字 `0`、字符串 `"0"`、布尔值 `false` 是三个不同事实，禁止互相替换。
- `wire_data_type` 继续表达 Neuron 协议类型；BIT 点位仍显示 `BIT`。
- BIT 的预期 L0 标量类型为 `INT`，有效值域为 `{0, 1}`。
- 数字 `0/1` 写入现有整数值字段，不写入布尔值字段；实时与历史使用同一契约。
- 来源摘要必须包含标量类型和值，因此数字 `0` 与布尔值 `false` 不能得到相同事实身份。
- 不建立新的 L0 表、不建立双值表、不增加第二条实时链。

L0 采用带类型的联合值。每条观测只允许一个原值字段非空；读取时依据观测实际非空字段恢复类型，不能再
只依据点位预期类型选择字段。这样即使 BIT 异常上传布尔值或字符串，平台也能保留原始证据并标记质量异常。

### 3.2 BIT 值域与质量

BIT 的正常输入是数字 `0` 或 `1`。收到 `2`、字符串或布尔字面量时：

1. L0 仍保存实际原值、时间和来源；
2. L0 有效质量变为 `BAD`，原因为 `BIT_VALUE_OUT_OF_RANGE` 或 `TYPE_MISMATCH`；
3. L1 不产生 GOOD 业务值；
4. L2 与上层消费者失败关闭。

平台不得丢弃异常原值，也不得强行转成布尔值。

## 4. L1 加工契约

### 4.1 直接使用

“直接使用”是真正的强类型原样传递：

- 只允许单输入；
- 输入和输出类型必须一致；
- 不执行类型转换；
- 不生成、解析或校验公式；
- 类型不一致在发布前以中文原因阻断。

实现层应使用明确的 passthrough 转换契约，不能继续把“直接使用”伪装成恒等公式。由此，直接使用流程
不再可能出现 `Formula syntax is invalid`。

### 4.2 `0/1` 转布尔

单个 BIT/INT 点位提供专用的 `0/1转布尔` 加工方法。实施工程师只配置：

- L2 实体名称与稳定业务标识；
- `1 表示 true` 或 `0 表示 true`。

输出类型自动锁定为 `BOOL`。平台把选择编译为现有安全公式能力的强类型规则，例如
`input == 1`，并在发布前展示人类可读规则。该方法复用现有 L1 编译、DAG、预检、版本修订和原子发布，
不引入第二套表达式或规则引擎。

## 5. 运行数据流

以 `15V电源故障` 为例：

```text
Neuron/MQTT：数字 0，协议类型 BIT
  → L0：值 0，实际标量 INT，质量 GOOD
  → L1：明确规则“原值等于 1”
  → L2：值 false，类型 BOOL，质量 GOOD
  → 告警/JDM/控制/EMS 工作台：只消费 committed L2
```

数据仍经过实时黑板、统一节拍、不可变数据帧和事务 A/B。数据库提交前不推送、不告警、不执行 JDM、
不控制。此次硬切不改变单写者、帧序、配置栅栏、STALE 或来源证据语义。

### 5.1 L2 异常投影

当新 L0 输入异常时，L1 产生带原因的 BAD 结果而不是假业务值。L2 latest 对人保留“上次正常值”，但
必须把以下时间和状态分开：

- 上次正常值及其原始数据时间；
- 当前质量 `BAD`；
- 本次异常时间与原因；
- 导致异常的 L0 来源证据。

界面必须写成“上次值：false；当前不可用”，不能把旧值显示成当前新值。告警值判断、JDM、控制和其他
机器消费者只允许 GOOD 输入，遇到 BAD/UNCERTAIN/STALE 一律失败关闭。

## 6. 用户界面

普通用户路径保持：

```text
选择真实设备 → 查看原始数据 → 勾选点位 → 加工为实体
→ 检查结果 → 发布实体 → 查看实体实时/历史/来源
```

### 6.1 原始数据

BIT 点位显示：

```text
当前值：0
协议类型：BIT
质量：正常
数据时间：……
来源：……
```

实时和历史都显示设备原始 `0/1`。页面不附加或存储 `false/true` 规范值。

### 6.2 加工抽屉

加工方法按输入能力提供：

- 直接使用；
- `0/1` 转布尔；
- 倍率与偏移；
- 状态映射；
- 高级公式。

选择 `0/1` 转布尔后，结果类型自动为 BOOL，预览明确显示：

```text
设备原值 0 → 规则“原值等于 1” → 实体值 false
```

只有“高级公式”显示并校验公式输入框。错误信息使用中文说明问题和处理办法，不能把内部英文错误码作为
普通用户唯一提示。

### 6.3 实体与来源

实体页继续提供实时、历史、质量、时间、来源与计算、修改、停用和重新发布。来源链显示：

```text
原始点位 0 → 0/1转布尔 → 全局实体 false
```

## 7. 现有配置与数据迁移

迁移采用硬切，不保留兼容 API、兼容视图、双写或运行期 fallback。

### 7.1 配置预检

迁移工具先扫描所有 `wire_data_type=BIT` 且预期类型为 BOOL 的点位及其活动 L1 依赖：

- 精确的 `BIT → BOOL 直接使用` 可确定为现有 `bool(0/1)` 语义，创建新的不可变 L1 修订，显式改为
  `0/1转布尔，1表示 true`；
- L2 实体 ID、定义键、名称及上层引用保持不变；
- 其他复杂 BOOL 公式不猜测、不自动发布，列入“需要检查”报告；
- 存在未解决阻断项时部署前置检查失败，禁止半迁移上线。

旧修订继续保留审计，但不参与新运行配置。

### 7.2 维护窗口

1. 完整备份数据库并验证备份文件可读；
2. 停止采集写入和帧处理；
3. 应用 Schema 与确定性配置迁移；
4. 清空运行测试数据：L0、L2、告警事件、数据帧、outbox 及运行游标；
5. 保留节点、点位目录、L1 模板/修订、L2 身份及其他配置；
6. 启动固定摘要镜像，进入 WARMING；
7. 收到活动依赖的全新 L0 后才进入 READY。

回退只能恢复维护窗口前数据库备份并启动旧固定摘要容器，不能让旧代码直接运行迁移后的数据库。

## 8. 验收

### 8.1 自动测试

- Raw adapter：数字 `0/1` 保持 INT；字符串与布尔字面量不被替换。
- BIT 值域：`0/1` 为 GOOD；`2` 和类型不匹配原值被保存但质量 BAD。
- PostgreSQL 往返：L0 history/latest、快照、outbox 和重启恢复保持原始值及类型。
- 来源摘要：数字 `0` 与布尔 `false` 身份不同。
- 直接使用：不触发公式编译，类型不一致在发布前阻断。
- `0/1` 转布尔：同时覆盖“1表示真”和“0表示真”。
- L2 失败投影：保留上次正常值和原时间，同时更新 BAD、异常时间、原因及来源。
- 配置迁移：确定性规则保留 L2 身份；复杂规则阻断部署。
- 前端：L0 实时/历史显示 `0/1`；加工预览和中文错误正确。

### 8.2 现场验收

部署 1 号机后必须确认：

- 新容器固定摘要、Schema、健康状态和重启次数正确；
- 最近窗口无 FAILED 帧、假 GOOD、半帧或 outbox 积压；
- 无头浏览器跑通
  `节点 → 原始数据 → 加工为实体 → 实体实时/历史/来源 → 告警`；
- 可见 Browser 沿同一主干抽查；
- 不执行控制、自动策略或设备写。

任一环节未通过，结论只能是 `INCOMPLETE` 或 `FAILED`。

## 9. 不做

- 不把数据库布尔值仅在前端格式化为 `0/1`；
- 不在 L0 同时永久保存原值和规范值；
- 不让“直接使用”隐式转换类型；
- 不新增规则引擎、消息系统、微服务或时序表；
- 不猜测复杂旧公式的业务含义；
- 不改变跨节点只能读取 L2、配置栅栏、事务 A/B 或统一上层 L2 消费边界；
- 不在本次验收中执行控制和自动策略。

## 10. 完成定义

只有数据契约、配置迁移、后端测试、数据库测试、前端测试与构建、无头主干、1 号机运行检查和可见
Browser 抽查全部通过，才能宣布完成。页面单独显示正确、单元测试单独通过或接口返回 200 均不足以
证明修复完成。
