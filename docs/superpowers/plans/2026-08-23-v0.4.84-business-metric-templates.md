# v0.4.84 Business Metric Templates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付八项光储充 EMS 业务指标模板，使实施工程师通过目录、来源预览和原子安装生成可修正、可审计且不能进入自动控制的 L2 统计实体。

**Architecture:** `BusinessMetricDelivery` 把版本化业务模板编译为既有点位加工修订和稳定 L2 实体；内部 `MetricProjection` 维护可恢复当前窗口，并只把完成/修正结果写入统一 L2 历史。`EntityCapabilityGuard` 递归检查点位加工与指标来源依赖，保证统计实体及其依赖链无法进入自动控制。

**Tech Stack:** Python 3.11、FastAPI、Pydantic、PostgreSQL/TimescaleDB、React、TypeScript、Tailwind、标准库 `zoneinfo`；不新增依赖。

**Spec:** `docs/superpowers/specs/2026-08-23-v0.4.84-business-metric-templates-design.md`

## Global Constraints

- 基线固定为 PR #48 的 `ea8b01e`，实现分支为 `ticket/v0.4.84-business-metric-templates`。
- 版本目标固定为 `v0.4.84-rc.1`，数据库目标固定为 Schema 043；不得改写 migration 001—042。
- 不新增 L3，不新建每指标/每节点超级表；正式历史只能写 `t_l2_observations`。
- 当前窗口投影不得写入 `t_l2_observations`；只有 `completed/corrected` 结果可以形成 L2 事实。
- 自动修正范围固定为滚动窗口 6 小时、日窗口 7 天、月窗口 35 天；超出范围必须管理员审批。
- 业务指标模板只能来自版本化解决方案资产；不提供通用表达式或 SQL 编辑器。
- 自动控制对统计实体和其完整依赖链 fail closed；前端隐藏不算安全门禁。
- 完成结果、修订和审计长期保留；高频明细保留期由单站配置冻结，窗口始终保留可验证证据摘要。
- 固定性能门槛为 500 个即时来源、100 个统计实体时 1 秒 tick p95 小于 500 ms，30 日重算小于 60 秒。
- 不新增依赖；时间区使用 Python 标准库 `zoneinfo`。
- 本计划不连接或部署 1 号机，不启用自动策略，不发送设备写命令。
