# ZiZu 配置式交付 v1 — Tracer-bullet 票据拆分草案 v2

> 来源规格：`docs/specs/configuration-delivery-v1.md`
> 状态：维护者已确认粒度、依赖和测试缝；已发布为 GitHub Issues #1–#19，使用仓库默认标签 `enhancement`。

## 01 — 建立最薄公开交付主缝

**Blocked by:** None

**What it delivers:** 实施工程师通过公开接口导入一个只含平台 liveness 验收项的最小解决方案包，查看计划、幂等安装并生成首份机器可读交付报告。

- [ ] 测试从公开包导入开始，以公开验收报告结束，不调用内部对象或 SQL。
- [ ] 包清单具有稳定 ID、Schema/包版本、平台兼容范围、资产摘要和验收引用。
- [ ] 校验失败零写入；相同包重复安装结果一致。
- [ ] liveness 成功/失败均产生稳定状态、机器码和证据。

**Interface / test seam:** 按
[`ADR-0006`](adr/0006-minimal-solution-delivery-tracer.md) 实现
`SolutionDelivery.import_package/plan_install/apply_install/run_acceptance`。主测试使用
真实 ZIP 和公开 HTTP，从导入走到不可变报告；辅助测试只断言模块接口的摘要、计划、
幂等和机器码。维护者确认 ADR 测试缝后才开始 TDD。

## 02 — 身份模块扩展到交付主缝

**Blocked by:** 01

**What it delivers:** admin、engineer、operator 可以登录；解决方案包和验收接口由服务端按角色保护，匿名调用被拒绝并留下审计。

- [ ] 三种角色具备明确身份，旧 `viewer` 有受控迁移。
- [ ] 包生命周期仅 admin，安装/验收允许 engineer，报告读取按明确权限执行。
- [ ] 登录、拒绝、包安装和验收进入审计。
- [ ] 主交付测试以真实认证身份运行。

## 03 — 将读与配置接口迁入角色权限

**Blocked by:** 02

**What it delivers:** operator 只能读取运行数据，engineer 可以配置节点、模板、实体、告警和策略，admin 保留系统级管理；现有客户端完成迁移。

- [ ] 公开权限矩阵覆盖所有非控制业务 REST 操作。
- [ ] 每个角色的允许/拒绝行为由接口集成测试证明。
- [ ] 前端使用真实登录身份，不再提交硬编码操作者。
- [ ] 旧匿名客户端获得明确迁移错误而非隐式成功。

## 04 — 收口控制、管理与 WebSocket 安全默认

**Blocked by:** 03

**What it delivers:** 控制/管理接口和 WebSocket 全部认证授权；生产仅最小 liveness 匿名，开发匿名必须显式开启并持续警示。

- [ ] WebSocket 建连和订阅执行与 REST 一致的身份/权限校验。
- [ ] 控制、Neuron、NanoMQ、SQL/清理类管理接口按动作授权。
- [ ] 生产匿名模式配置导致启动失败；开发匿名显示不安全状态。
- [ ] OpenAPI 声明安全方案且端点覆盖测试无遗漏。

## 05 — 强类型参数与 Secret 安装计划

**Blocked by:** 01, 02

**What it delivers:** engineer 通过公开安装流程填写强类型站点参数和 Secret 引用，在执行前看到新增、变更、保留和阻断项。

- [ ] 支持首个 EMS 包所需类型、单位、必填、默认值、范围和枚举。
- [ ] Secret 只保存引用，响应、日志、导出和报告不回显值。
- [ ] 参数/Secret 缺失时计划被阻断且站点零变更。
- [ ] 执行成功生成不可变站点配置版本和审计。

## 06 — 单设备实体实例与确定性绑定

**Blocked by:** 05

**What it delivers:** 包的一个设备槽位生成稳定实体实例，engineer 通过可解释候选确认唯一物理点位；缺失或歧义阻止交付就绪。

- [ ] 定义、实例、实例槽位和绑定各有稳定 ID/清晰职责。
- [ ] 唯一候选显示匹配理由；零/多候选有稳定阻断码。
- [ ] 运行读取只使用已确认主来源，不按优先级/创建顺序猜测。
- [ ] 交付报告证明绑定完整、唯一和数据新鲜。

**Interface / test seam:** 按
[`ADR-0005`](adr/0005-entity-instance-registry-and-deterministic-binding.md) 实现
`EntityInstanceRegistry.plan/apply/resolve`；辅助测试只断言公开计划、稳定机器码、
实例身份、幂等和确认来源，主交付缝从公开包/API 经协议模拟器到机器验收报告。
维护者确认 ADR 的两个测试缝后才开始 TDD；实现仍被票据 05 阻塞。

## 07 — 扩展多设备实例并迁移实体消费者

**Blocked by:** 06

**What it delivers:** 多台同类 PCS/BMS 等拥有互不混淆的实体实例；规则、告警、控制和运行配置逐步以实例 ID 取代全局实体引用。

- [x] 同一定义可生成多设备实例，显示名变化不破坏引用。
- [x] 旧全局实体迁移预览区分唯一归属、缺失和歧义。
- [x] 首批迁移的规则输入只接受实例 ID；旧规则只读兼容并返回迁移警告。
- [x] 主备来源只通过显式人工故障切换策略表达并追加审计；数据质量不触发自动切换。

**Implemented boundary:** Ticket 07 迁移规则输入，并建立告警、控制和 EMS 工作台复用的
实体实例目录与外键引用基础。规则控制输出由 Ticket 08/10 迁入统一控制命令，告警与工作台
分别由 Ticket 12/15 迁移，避免在消费者状态机尚未成立前保留新的直写旁路。

## 08 — 扩展统一控制命令并迁移实体写入

**Blocked by:** 04, 06

**What it delivers:** operator 对可控实体发起统一控制命令，经过权限、类型、限值、联锁、幂等和持久冷却后下发，并以现场回读作为成功判据。

- [x] 状态覆盖受理、校验、下发、回读确认及拒绝、超时、失败、不一致。
- [x] 写成功但回读不一致进入 `mismatch`。
- [x] 服务重启不绕过幂等/冷却，也不丢失在途状态。
- [x] 高风险命令支持绑定内容和主体的短期二次确认。

**Interface / test seam:** 按
[`ADR-0007`](adr/0007-unified-control-command-runtime.md) 实现
`ControlCommandRuntime.request_confirmation/submit/reconcile/get`。辅助测试只断言公开命令
状态、机器码和不变量；主交付缝从解决方案包/API 经协议模拟器到回读确认。本文 ADR
记录的两个测试缝已由维护者的产品目标确认，并已完成 TDD。Neuron 与 MQTT RPC 兼容入口
已由票据 09 迁入统一命令；遗留实体、规则与策略直接写仍由票据 10、11 逐一迁入，不能据此
宣称全站写入已经统一。

## 09 — 迁移 Neuron 直写与 MQTT RPC

**Blocked by:** 08

**What it delivers:** `/neuron/write` 和 MQTT RPC 兼容入口转换为控制命令并返回命令 ID，不再直接宣称设备成功。

- [x] 两条旧路径均经过统一校验、持久状态、审计和回读。
- [x] Neuron 403/不可达时命令及验收明确失败为控制非就绪。
- [x] 兼容响应包含迁移提示和命令查询入口。
- [x] 没有来自这两条接口的直接设备写旁路。

## 10 — 迁移规则与策略控制动作

**Blocked by:** 07, 08

**What it delivers:** 规则命中只创建统一控制命令，自动动作与人工控制共享联锁、冷却、审计和回读。

- [x] 规则输出引用实体实例，不直接包含 Neuron 地址细节。
- [x] 自动命令标识规则/策略主体及触发证据。
- [x] 进程重启后冷却仍有效。
- [x] 可重放场景证明策略命中到回读确认全链路。

## 11 — 删除设备写入旁路

**Blocked by:** 09, 10

**What it delivers:** 生产运行中只有控制命令模块能够调用设备写适配器，所有兼容入口均已迁移或关闭。

- [x] 静态检查和集成测试证明业务调用方不能直接写设备。
- [x] 旧同步“写成功”响应语义被移除。
- [x] 旁路关闭有迁移说明、版本边界和回归测试。
- [x] 控制深模块的外部接口保持小而稳定。

## 12 — 扩展统一告警状态机并迁移实体来源

**Blocked by:** 06

**What it delivers:** 实体观测驱动一个告警事件经历 normal、pending、active_unacknowledged、active_acknowledged、recovered；确认不等于恢复。

- [x] 支持续时、迟滞、恢复条件和通知节流。
- [x] 一次连续故障只形成一个活动事件，不按采样累加。
- [x] 仍活动时不能人工恢复。
- [x] 报告证明触发、确认和现场恢复证据。

**Interface / test seam:** 按
[`ADR-0004`](adr/0004-unified-alarm-state-machine-interface.md) 实现
`AlarmRuntime.submit(observation)` 与 `acknowledge(command)`；状态机辅助测试只从这
两个接口断言外部状态和不变量，主交付缝从公开包/API 到机器验收报告。维护者确认
ADR 的测试缝后才开始 TDD。

## 13 — 迁移标签与 MQTT 告警来源

**Blocked by:** 12

**What it delivers:** 标签和 MQTT 告警适配器只提交统一现场观测，不再维护各自的生命周期和采样计数语义。

- [ ] 三种来源的相同条件得到一致状态转换。
- [ ] 来源细节作为证据保留，不改变统一状态接口。
- [ ] 高频采样不会制造事件/通知风暴。
- [ ] 旧记录保留只读，不猜测性重写历史。

## 14 — 迁移规则告警并删除人工恢复旁路

**Blocked by:** 10, 13

**What it delivers:** 规则告警进入统一状态机，旧人工 resolve 和三套独立生命周期被关闭，告警统计回归事件语义。

- [ ] 规则只提交观测/条件，不直接插入或恢复告警。
- [ ] API 仅允许确认活动告警，没有伪造恢复的路径。
- [ ] 所有新告警含定义版本、实体实例和状态转换审计。
- [ ] 静态/集成检查证明旧告警旁路不再可用。

**Contract gate:** 删除 `POST /alarms`、`PUT /alarms/{id}/resolve` 和前端人工恢复
按钮，并撤销应用对旧 `t_alarms` 的写权限；旧历史只读保留，不重建新状态。

## 15 — 可配置 EMS 运行工作台

**Blocked by:** 04, 07, 11, 14

**What it delivers:** 包配置固定 EMS 工作台的导航、分组、KPI、趋势、告警和控制入口，operator 不改前端源码即可运行站点。

- [ ] 仅允许平台组件白名单和实体实例引用，无任意前端代码。
- [ ] operator 可查看实时/历史、确认告警并发起授权控制。
- [ ] 缺失引用/权限在安装或运行时明确失败。
- [ ] 改变包配置能改变站点分组和指标而无需源码变更。

## 16 — 基础 EMS 策略与仿真验收

**Blocked by:** 10, 15

**What it delivers:** engineer 从包启用一个基础 EMS 策略，启用前验证输入、单位和仿真用例，动作走统一控制闭环。

- [ ] 缺失输入或量纲不兼容时不能启用。
- [ ] 至少一个公开、固定、可重放的 EMS 仿真场景通过。
- [ ] 报告包含输入、仿真、命令和回读证据。
- [ ] 自动动作不具备人工控制之外的旁路权限。

## 17 — 三方升级保留站点覆盖

**Blocked by:** 05, 07, 15, 16

**What it delivers:** engineer 比较旧包、当前站点和新包，自动保留无冲突覆盖并逐项解决冲突，失败不留下半升级配置。

- [ ] 计划区分新增、包变更、站点覆盖、删除候选和冲突。
- [ ] 未覆盖项跟随新包，站点覆盖默认保留。
- [ ] 双方修改、删除运行引用及安全语义变化会阻断。
- [ ] 成功生成新站点版本；失败可安全重试。

## 18 — 不可变多架构发布与完整 EMS 包

**Blocked by:** 04, 11, 14, 16, 17

**What it delivers:** 固定 digest 的 x86_64/ARM64 平台制品与完整光储充 EMS 包组合成可重现发布，报告锁定平台、Schema、包及站点配置版本。

- [ ] 正式发布拒绝 `latest` 和宿主机源码覆盖。
- [ ] fresh/upgrade migration 自动验证并暴露 Schema 版本。
- [ ] PCS、BMS、PV、EVSE、关口电表资产与验收项完整且不含现场私密数据。
- [ ] 统计证明至少 90% 点位、实体、告警和策略由包/公开 UI/API 配置。
- [ ] 回滚仅选择已验证且 Schema 兼容的发布锁定。

## 19 — 四小时独立交付试验

**Blocked by:** 18

**What it delivers:** 未参与开发的 engineer 在干净环境中，只用公开文档、不可变制品、解决方案包、UI/API 和测试设备，在四小时内交付完整光储充 EMS。

- [ ] 参与者、环境、起止时间、人工/自动步骤和失败点完整记录。
- [ ] 无源码修改、SQL、临时脚本或开发人员口头指导。
- [ ] 四小时内完成且配置覆盖率至少 90%。
- [ ] 机器验收报告全部必需项通过；失败如实转为后续票据。
